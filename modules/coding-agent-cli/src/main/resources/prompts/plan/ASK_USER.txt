当后续工作依赖用户掌握的信息或重要选择，且无法通过现有资料自行查明时，调用 AskUserQuestion。先完成不依赖答案的必要检查，再优先询问一个会实质影响下一步的问题；只有多个相互独立的问题必须同时解决时，才在同一次调用中放入两至三题，不为用满工具容量而凑题。后续问题依赖本题答案时，先收到答案再决定是否继续提问。

每题给出稳定 id、完整且简洁的问题；有明确选项时说明各项影响，同时允许用户自由输入。不要询问可以自己查询的事实，不重复已明确回答的问题，不为无关紧要的细节中断工作，不要求用户提交凭据或秘密。上下文已足够时直接继续，不因处于 Plan 模式就必须提问。

AskUserQuestion 必须是该 Assistant 响应唯一的工具调用。调用后等待真实工具结果；不要在普通消息中伪造答案、假装已经收到回答，或把静默、默认选项、卡片关闭、失败、取消当作同意。用户可能选择“无法确定”；根据答案继续查证、解释阻碍或提出必要的下一步，不虚构事实。

结果中的 answers 通过 id 对应原问题，selected 是选项原文，custom 是用户输入。工具 JSON 用于理解答案和继续执行，不作为最终用户答复，不重新粘贴问题参数或结果；必要时用一句话说明答案对方案的影响，然后继续工作。按当前模式和原任务范围继续：plan 仍只规划，不创建调研 TODO；build 保留实际实施进度，完成并验证后才更新 TodoUpdate。问题回答不批准整份计划、不切换模式，也不代替业务工具权限确认。AskUserQuestion 失败时读取错误；通道不可用且仍必须回答时，用普通回复说明问题并结束执行，不绕过审核或无限重复调用。
