ADR-0007 · 控制面合入 agent-core 而非独立 sidecar 模块

Status: Accepted · Date: 2026-06-18 · 设计文档: control-plane

Context

控制面 v1 最初设计为独立 Spring Boot sidecar 进程（modules/agent-control-plane/），有自己的 @SpringBootApplication、application.yml、端口 8090。但 CampusClaw 的 mate-campusclaw 镜像是单模块结构——sync 脚本把 modules/{ai,tui,agent-core,cron,coding-agent-cli} 的 Java 源码合并到同一个 jar。如果 agent-control-plane 也进镜像，两个 @SpringBootApplication 类会被 Spring 同时扫到，产生 bean 定义冲突；两份 application.yml 也会互相覆盖。

此外，control-plane 原版用 spring-boot-starter-web（servlet/Tomcat），而 coding-agent-cli 用 spring-boot-starter-webflux（reactive/Netty）。同一 classpath 下 servlet 与 webflux autoconf 不能共存，Spring Boot 会拒绝启动或行为不确定。

Options considered

  • Keep agent-control-plane as standalone module, exclude from mate mirror — rejected: mate 镜像不含 control-plane 代码，公司 mate parent 项目无法集成控制面能力；sync 脚本需要永久维护黑名单；根 pom 的 sidecar 注释需要 ADR 才能移除。
  • Keep standalone module, merge into mate with resource isolation — rejected: 需要改造 sync 脚本支持多模块资源隔离（application.yml 分文件、@SpringBootApplication 去重），工程量大且 sync 脚本变复杂；servlet vs webflux 冲突仍需解决。
  • Merge control-plane code into agent-core + coding-agent-cli, drop standalone module (chosen) — domain/service 放 agent-core（库逻辑），controller/routes 放 coding-agent-cli（web 绑定），共用 coding-agent-cli 的 webflux stack 和 CampusClawApplication 主类。sync 脚本无需改动（agent-core 已在 MODULES 白名单）。

Decision

  • 删除 modules/agent-control-plane/ 整个模块
  • domain（NodeInfo / NodeStatus / NodeMetrics / RuntimeCapability / ScheduleRequest / ScheduleDecision）+ service（NodeRegistry / RuntimeScheduler / HealthCheckScheduler）+ config（ControlPlaneProperties / ControlPlaneConfiguration）放 modules/agent-core/src/main/java/com/campusclaw/agent/controlplane/
  • web 层（NodeRoutes / RuntimeRoutes / HeartbeatRequest / RegisterNodeRequest / ControlPlaneExceptionHandler）放 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/controlplane/
  • control-plane 配置合并进 modules/coding-agent-cli/src/main/resources/application.yml 的 controlplane.heartbeat.* 块
  • sync 脚本 MODULES 列表不变（agent-core + coding-agent-cli 已在列表，control-plane 代码自动同步到 mate）

Consequences

  • 正面：mate 镜像自动包含 control-plane 代码，无需改 sync 脚本；单一 JVM 进程跑 coding-agent + control-plane endpoints，运维简化；webflux 技术栈统一
  • 正面：CampusClawApplication 的 scanBasePackages = "com.campusclaw" 自动扫到 control-plane bean，无需额外 @ComponentScan
  • 负面：agent-core 引入了 spring-boot 主 artifact（为 @ConfigurationProperties 注解），不再是纯 spring-context 库
  • 负面：control-plane HTTP 端点只在 --mode server 时可用（reactor-netty 启动时），非 server 模式下 control-plane bean 存在但不监听端口
  • 后续：如果未来 control-plane 需要独立扩缩容（与 coding-agent 分开部署），需要重新拆分——但 v1 阶段单进程足够
