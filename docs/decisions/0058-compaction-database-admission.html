ADR-0058：分离压缩数据库观察与原子准入

Date：2026-09-07 · Version：1.0.1

Context

原 6b1 仅支持已准入执行；在严格模块 850 行、含镜像 1800 行软上限下，完整准入与 Runtime 接入当时按职责串行交付。 本 PR 只实现 Repository 观察、复核和事务验证，空历史的整个命令行为仍属于 6b2b。

Java 基线 14769188538eaa2f1df1e25ef2fef40d87ceafed；目标设计只读基线 pi-mono-java-design@2734a36b6f3cee2ebe16f1133d50ccb3eaaeb4e9， 04-命令与技能/01-内置命令/README.md §3、§7，版本 2.7.1。

基线源码：modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/persistence/MyBatisRuntimeSessionRepository.java 的 acceptUserEvent/updateName/updateModel/updateThinking 已以 Session 行锁串行化； modules/coding-agent-cli/src/main/resources/mapper/session/RuntimeSessionMapper.xml 的 lockSessionForUpdate/listCurrentBranchEntries/markSessionRunning 提供复用的 SQL。

选项与取舍

  • 单事务内做完整 Agent 准备：无需再次复核，但长时间占用行锁，并混入文件/网络/资源责任，不采用。
  • 普通无锁读取后直接标 running：简单，但可能恢复过期分支或配置，不采用。
  • 行锁观察、锁外准备、行锁复核：增加一次事务，但划清持久化与执行职责，采用。锁外准备和执行在 6b2b 实现。

Decision 与理由

  • 新增 observeCompaction 返回仅数据的 DTO；同一行锁读取 Session 与完整当前分支，空或忙观察不写数据。
  • 新增 acceptCompaction 复核 idle、activeLeafId、modelId、thinking，拒绝过期历史与配置。
  • 不比较旧 resourceVersion，因 Name-only 更新不影响压缩上下文；状态写入使用当前版本加 1，保留名称和叶节点。
  • 不生成合成 Entry、Usage、公开 commandId 或生命周期存储；不更改现有 PUT、POST Events 和 schema。
  • 通过已有 SQL 的受影响行数检查及 Spring 事务保持失败回滚；资源准备、接入和清理仍须由后续 Service 完成。

pi 基线 4af9d21d3b4d664e4a29fcabfec85171077248e3 的 packages/coding-agent/src/core/agent-session.ts:compact/abortCompaction 观察分支、准备并写压缩结果， 不提供 Java 数据库准入。idle-only、空历史 no-op、禁止队列是产品约束；两阶段事务是架构差异，不能归为 pi 现有行为。

Consequences

  • 正面：观察与接受有明确线性化时点，防止跨进程用旧上下文启动，允许并发改名。
  • 代价：完整历史 O(N) 内存，现有递归分页有重复回溯成本；繁忙 Session 的更新需等待短期数据库事务。
  • 边界：本次仅证明空观察零写入；未交付容量跳过、内部 Usage 身份、Runtime 接入、失败资源回收或命令/HTTP。
  • 后续职责：6b2b 补上述能力与完整链路测试，不将其他 Events/前端迁移加入前置条件；旧先合入再开发安排仅保留为历史过程。
  • 提交结果不确定不能盲目恢复 idle 或重放；当前 PR 不宣称提供数据库失联或进程崩溃的执行恢复。

验证

单元测试检查分支、分页、无额外写入及受影响行数。真实 openGauss 验证 Spring/MyBatis 事务、501 条完整分页、 空观察/拒绝零写入、并发 Name 保留、回滚和跨 JVM 的 Compact/POST Events 竞争；具体运行结果见实现设计。
