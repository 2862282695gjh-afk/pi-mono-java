Context

变更前前端没有自定义请求 Header 的入口。适配器为普通请求内部生成 Accept、Accept-Language、Content-Type 和非秘密的 X-HW-ID，开发者无法从页面为一次消息提交补充调用上下文。

后端已在初始 POST /sessions/{sessionId}/events 读取契约识别的凭据 Header，并只在当次 Agent 执行及其 Child 调用期间由内存对象持有。前端调试入口需要允许协议快速试验，但不应预设 JWT、APPKEY 或“双凭据”等模式，也不应把自动生成的 Header 暴露为可编辑清单。

Decision drivers

  • 允许开发者输入当前或未来协议所需的任意合法 Header 名称和值。
  • 保持 Header 编辑器与 Agent/Session 诊断职责分离。
  • 把临时值限制在开发构建、当前页面和一次初始 Events 请求中。
  • 避免通过预置项、说明注释或隐藏 Header 列表把后端内部实现固化为前端信息架构。

Considered options

提供 JWT、APPKEY 与兼容模式

优点：常见凭据组合输入较快。
缺点：把当前凭据名称和组合固化在 UI，无法覆盖其他协议 Header，也会重复后端规则。拒绝。

把 Header 字段放入开发者诊断入口

优点：减少一个顶部入口。
缺点：混合请求构造与 Session 诊断，入口名称和内容不再匹配。拒绝。

使用独立通用 Headers 面板

优点：Key/Value 与 HTTP 原语一致；不依赖特定凭据模式；可复用原开发者诊断入口的紧凑视觉。
缺点：开发者需要自己知道目标接口接受哪些 Header。接受。

Decision

  • 开发构建的顶部工具区提供独立折叠入口，名称固定为 Headers，不与开发者诊断入口合并。
  • 编辑器使用通用 Key/Value 行。每行支持启用、删除；编辑尾行时自动增加空白行；摘要显示有效 Header 数量；清空后恢复一条空白行。
  • 界面不提供凭据模式、固定 Header 名、说明注释、自动生成 Header 行或“隐藏请求头”列表。
  • 已启用的半空行、非法 HTTP token、Fetch 无法表示的值、Fetch 禁止请求 Header 和大小写不敏感重复名称阻止提交。折叠面板会先展开并等待 Vue 完成渲染，再聚焦首个错误所在的 Key 或 Value。
  • Fetch 规则按名称和值共同判断：包括 Set-Cookie 与 proxy-/sec- 前缀；X-HTTP-Method、X-HTTP-Method-Override、X-Method-Override 仅在拆分后的值包含 CONNECT、TRACE 或 TRACK 时拒绝。
  • 值只保存在当前 Vue 组件状态和必需的表单 DOM，不写入 localStorage、sessionStorage、IndexedDB、日志或设计 fixture；刷新页面即清空。
  • 普通消息提交时创建一次 Headers 副本，仅传给初始 Events POST。Session 创建/读取、Events 历史对账、模型/Thinking 配置、Steer、FollowUp、Abort 和断流恢复均不接收该副本。
  • 适配器继续内部生成默认 Header。开发者手工填写同名 Key 时，在请求合并阶段按 Fetch Headers 的大小写不敏感语义覆盖默认值。
  • 前端会把所有已启用且合法的自定义 Header 发送到 Runtime Events endpoint；后端只读取其契约明确识别的名称，其他名称不会进入后续 Agent 执行上下文。

Intentional differences

产品约束：采用 Postman 风格的通用行模型，但保留 CampusClaw 原有暖灰虚线视觉，不复制 Postman 的完整标签页、批量编辑或自动 Header 展示。

架构变化：前端从“请求 Header 全由适配器生成”改为“初始 Events POST 可合并一次开发者副本”；其他请求签名保持不接收该副本。

安全加固：开发工具只在 import.meta.env.DEV 下渲染；输入不持久化，非法值在 Fetch 前被拒绝，断线不会重放带副作用 POST。

Consequences

  • 正面：新增 Header 不需要改动组件结构或增加凭据模式。
  • 正面：自动 Header 保持内部实现细节，页面只呈现开发者主动输入的内容。
  • 正面：通过函数签名和契约测试证明临时值不会扩散到读取、配置和控制请求。
  • 负面：输入值仍会出现在当前页面输入元素和浏览器网络面板，因此该能力只能用于受控开发环境。
  • 负面：浏览器平台禁止设置的 Header 无法用此工具覆盖，错误会在发送前显示。

Validation

  • frontend/src/debugHeaders.test.ts 覆盖合法行、HTTP token、非法值、Fetch 名称+值算法、大小写不敏感重复名称，以及折叠面板先展开再聚焦精确错误字段。
  • frontend/src/composables/useRuntimeApi.test.ts 覆盖自定义值覆盖默认 X-HW-ID，并验证临时 Header 只出现在初始 Events POST。
  • npm test、npm run typecheck、npm run build 和多视口开发构建浏览器检查覆盖功能、类型、打包和响应式呈现。
