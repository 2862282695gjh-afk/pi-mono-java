ADR-0027：Assistant 安全富文本采用 Token-to-VNode 投影

Context

基线实现通过 Vue 文本插值显示 Assistant text，因此模型返回的表格管道符、标题标记、反引号和列表标记会直接暴露给用户。Runtime 已把 delta、completed 和 GET history 的 Assistant TextContent.text 作为普通文本原样传递，没有服务端 HTML，也没有可信富文本边界。

Assistant 输出、用户输入和工具结果具有不同信任与产品语义。若统一开启 Markdown 或直接插入 HTML，模型和外部系统内容可产生脚本、跟踪图片、危险协议链接或伪造应用内操作。

Decision drivers

  • 表格、列表、引用、强调和代码需要语义化、可选择、可访问的显示。
  • 流式 preview、completed 替换和历史恢复必须由同一份原文得到结构等价的最终结果。
  • 不可信内容不得变成 HTML 字符串、事件属性、远程图片请求或任意协议导航。
  • 超大或异常输入必须可预测地回退，不得白屏、截断原文或阻塞主线程。

Considered options

继续显示纯文本

Pro：安全与实现最简单。
Con：表格、代码和层级结构难以阅读，正是本次用户反馈的问题。拒绝。

Markdown 直接生成 HTML，再用 sanitizer 和 v-html 插入

Pro：生态成熟、实现代码少。
Con：系统仍需维护 HTML 字符串信任边界和 sanitizer 配置；Vue 模板无法对每个节点、属性、复制行为与可访问性进行静态控制。拒绝。

Markdown token parser 加自有 allowlist，再创建固定 Vue VNode

Pro：复用成熟语法解析，同时由应用完全控制可出现的元素、属性、URL 与交互；无需 HTML 注入。
Con：需要维护 token 到中间树及 VNode 的映射，并为流式边界与降级补充测试。接受。

自行实现完整 Markdown parser

Pro：依赖最少。
Con：CommonMark/GFM 边界复杂，安全和兼容维护成本明显更高。拒绝。

Decision

  • Assistant turn 使用 rawMarkdown 保存唯一原文；delta 追加，completed 以持久化全文替换。Runtime、SSE 与历史契约不新增 HTML 字段。
  • 使用 MIT 许可的 markdown-it 15.0.0，显式关闭 raw HTML、linkify 和 typographer，只消费 parser token，不调用其 HTML renderer。
  • 应用中间树只允许段落、h2-h4、列表/只读 task、强调/删除线、引用、分隔线、行内代码、代码块、GFM table 与链接。表格对齐只能取 left、center 或 right。
  • 只有无嵌入凭据的绝对 http:/https: URL 可以点击，并统一使用新窗口与 noopener noreferrer。相对 URL 和其他协议降级为不可点击文本。
  • Markdown 图片只显示替代文字占位，不创建 img 或发起网络请求。raw HTML 作为文本显示。User、Tool result 和 Error 继续使用纯文本或专用 viewer；Thinking 的安全摘要边界由 ADR-0028 约束。
  • Vue 只使用 h() 创建固定 VNode；禁止 v-html、innerHTML 和字符串拼接事件属性。
  • streaming 更新每个 animation frame 至多解析一次；只有空行边界前的稳定块进入 parser，未闭合尾部保持纯文本。completed 立即执行完整解析，并播报一次“回答已完成”。
  • parser 嵌套上限为 32；源文本超过 200,000 字符、中间树超过 10,000 节点或解析异常时，显示未截断纯文本和降级提示。公共 Chat 契约仍需独立冻结消息大小上限。

Consequences

正面：Assistant 表格、列表和代码可读；所有消息来源复用同一渲染器；不建立 HTML 信任面；图片、链接、复制和可访问性行为可由组件集中控制。

负面：运行包增加 Markdown parser 及其依赖；流式尾部会在安全边界出现前暂时显示 Markdown 标记；语法扩展必须同时更新 allowlist、渲染器、样式和安全测试。

安全影响：这是安全加固，不表示模型输出可信。CSP、公共 bridge 的事件投影、错误脱敏和浏览器认证边界仍然必须独立成立。

后续：公共 Chat 契约评审时冻结消息大小和附件媒体策略；浏览器 E2E 增加多视口溢出、键盘滚动、Clipboard 失败与网络请求观察。

Validation

  • richText.test.ts覆盖语法、HTML/图片/URL 边界、任务列表、表格对齐、流式尾块和预算降级。
  • 前端必须通过 npm test、npm run typecheck、npm run build 和高危依赖审计。
  • 设计图必须由 ASCII-only PlantUML 生成并验证为 XML；Markdown 不得包含 Mermaid。
