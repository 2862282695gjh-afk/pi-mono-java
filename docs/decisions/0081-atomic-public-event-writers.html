ADR-0081：统一公共事件工厂并原子持久化配置事件

Status: Accepted · Date: 2026-09-08 · Version: 1.0.1

Context

Events v2 要求 SSE 完整帧与 GET 历史读取同一份权威公共事件。模型/Thinking HTTP、 Builtin Command 和消息接受前的模型校准共用配置 Service，但变更前只写内部配置 Entry。若在配置事务之后另写公共事件， 故障会留下已变更配置却缺少历史的半份状态；若各调用者自行编码，内部点号类型、公共下划线类型和字段规则会发生漂移。

设计基线为 pi-mono-java-design@2ee2a321，变更前 Java 为 f5c3a755。 pi 基线 5cd93f68 的 packages/agent/src/agent-loop.ts#runAgentLoop 和 #prepareToolCall 负责模型和工具事件循环， 没有 CampusClaw 的配置资源、数据库事务或 HTTP 公共事件表。

Decision

使用唯一的 RuntimeCommittedEventFactory 从已安全定稿领域对象构造 CommittedEventDTO。配置工厂读取最终 RuntimeEntryDTO，将内部 session.model.changed/session.thinking.changed 转为公共 session.model_changed/session.thinking_changed，并复用 Entry ID 和时间。

为 RuntimeSessionRepository.updateModel/updateThinking 增加接收公共事件工厂的组合重载。 MyBatis 实现在现有 Session 行锁和 Spring 事务内完成配置状态更新、Entry、公共事件、精确投影标记、active leaf、 resource version 与共享序号。公共事件时间在入库前统一到 UTC 毫秒；任一步失败都回滚。

生产模型/Thinking 配置 Service 和自动模型校准只使用组合重载。旧重载暂供尚未切换的内部调用， 不能作为新的公开配置写入点。配置 HTTP 与 Builtin Command 的响应形态保持不变，事件只进入权威历史。

考虑过的选项及取舍

  • Service 在配置提交后另开事务写公共事件。 Pro：Repository 接口较少。Con：进程故障和第二次提交失败会永久留下半份历史，违反完整性门禁，因此不采用。
  • 每个 HTTP、Command 和校准入口分别构造公共 JSON。 Pro：调用路径直观。Con：安全字段、错误文案、工具参数和类型转换会复制，难以保证 POST/GET 同形，因此不采用。
  • Repository 接收最终 Entry 的事件工厂。 Pro：工厂获得真实锚点、时间和身份，全部写入共享事务；Service 仍掌握业务准入。Con：端口增加组合重载，测试需同时验证函数调用与数据库回滚。采用此方案。

所选方案与理由

配置变化本来就由 Repository 持有 Session 行锁并分配内部序号，在该事务中调用纯本地公共事件工厂， 可以用最小锁范围获得故障原子性。统一工厂把安全公开字段与持久化细节分开，也允许执行生命周期后续复用同一构造入口， 避免出现第二套投影规则。

Consequences

正面结果是 HTTP、Builtin Command 和自动校准产生完全相同的配置公共事件；模型切换自动关闭 Thinking 时，两条事件保持锁内顺序；同值请求不增加事件。每条配置 Entry 增加一条公共事件和一条完整性标记写入， 没有新增线程、网络请求或 Maven 依赖。

负面影响是 Repository 暂时保留两组配置重载，旧入口不提供 v2 完整性保证，需要在所有内部调用切换后清理。 本决策只接通配置写入，并不单独切换 Events GET/POST；执行期事件、运行时完整性门禁和请求级 SSE 必须在后续集成验证后统一上线。 当前产品是第一版，只使用全新安装 schema，不提供旧数据迁移。
