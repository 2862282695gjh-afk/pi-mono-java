ADR-0059：接通压缩准入与 Runtime 执行

Status：Accepted · 已确认的 6b2b 实施切片
Date：2026-09-07 · Version：1.0.0

Context

6b2a 提供行锁观察/接受，6b1 提供已接受执行。需要一个内部 Service 连接两者，保证有效空上下文先于资源准备、 真实执行有独立 Usage 身份，并区分数据库拒绝、提交结果不确定和已接受后的失败。当前不发布公共 Command/HTTP。

Java 基线 6f52fddc87a03c20916fc7b6ef1de87f6a7a8cf5；只读目标设计 pi-mono-java-design@2734a36b6f3cee2ebe16f1133d50ccb3eaaeb4e9， 04-命令与技能/01-内置命令/README.md v2.7.1 §3、§7。未修改设计仓。

已观察 Java 源码位于 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/： runtimeapi/persistence/MyBatisRuntimeSessionRepository.java:observeCompaction/acceptCompaction、 runtimeapi/compaction/RuntimeCompactionCoordinator.java:start、 runtimeapi/runtime/RuntimeSessionEngineRegistry.java:createHolder/complete； 新 Service 是本 PR 实现，不是基线已有入口。

考虑过的选项

  • 复用 POST Events 接受一条人工用户消息：可复用整套入口，但污染历史/Usage 身份且带入 SSE/队列，不采用。
  • 先准备 Agent 再判断历史为空：流程单一，但空操作仍依赖 Agent 和容量，不满足 no-op，不采用。
  • 单独 Runtime Service 连接现有窄端口：增加少量编排，保留各层责任与空操作零副作用，采用。

Decision 与理由

  • 共用操作锁，先数据库观察和 Codec 判空；空时返回 false，不准备 Agent/模型、内部身份或运行资源。
  • 非空时准备当前模型和恢复消息，注册 Holder，数据库复核成功后交给既有 Coordinator/Projector。
  • Registry 关闭初始化中途失败的 Managed Session，close 失败仍保留原异常并归还容量。
  • 明确拒绝和未知提交仅清理本次进程内资源；只有明确 ACCEPTED 后才允许尝试恢复数据库 idle。
  • 复用隔离完成句柄、Compaction Entry + 内部 Usage、30 分钟预算及终态清理；不接队列、不延长 Mate 凭据作用域。

pi 4af9d21d3b4d664e4a29fcabfec85171077248e3 的 packages/coding-agent/src/core/agent-session.ts:compact/abortCompaction 会读取分支、生成摘要、 写 Compaction 并重建上下文；不存在本方案的数据库准入。idle-only/no-op/无队列是产品约束， 共享资源与事务接入是架构差异，未知提交不盲目写 idle 是安全加固。

Consequences

  • 正面：空上下文不受 Agent/容量可用性影响；拒绝不会覆盖竞争执行；真实链路有可验证的 Entry/Usage 身份。
  • 代价：恢复完整历史为 O(N)，准备期间仍持本地操作锁；数据库不可用时无法保证持久化 idle。
  • 限制：不提供未知提交或进程崩溃恢复；不自动重放。30 分钟是接受后执行预算，不包含准备阶段。
  • 后续：本 PR 合入后串行接 Compact Handler/Contributor、Builtin/Skill 共享应用层及 HTTP，保留最终跨进程验收。

验证

真实 Runtime Service → ManagedAgentSession/SessionCompactor → Coordinator → Projector → openGauss； 外部模型使用可控响应。验证空上下文、调用方取消、真实 Entry/Usage、恢复、异常和数据库竞争； 单元测试覆盖初始化 close 异常、容量和操作锁。具体命令、结果和未验证项见实现设计及 PR。
