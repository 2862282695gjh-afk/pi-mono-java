Context

根 Dockerfile、根 MateService Kubernetes 清单和 modules/k8s 源于本地工具沙箱及其后的单容器过渡方案。当前产品已经移除 Docker Sandbox、DinD 和 Hybrid Tool，仓库现阶段也不维护正式 Kubernetes 部署框架。

这些资产已经与当前源码不一致：Dockerfile 复制不存在的 TUI POM；Kubernetes 清单没有提供当前应用所需的 CampusMate 和 GaussDB 配置；健康检查、ConfigMap、存储和环境变体也没有形成可验证的交付链。继续保留会把历史样例误表达为当前受维护能力。

Decision drivers

  • 让仓库内容准确反映当前产品和交付边界。
  • 避免为尚未设计的 Kubernetes 框架提前固化镜像、配置、存储和网络决策。
  • 删除已失效且没有 CI 验证的部署入口，降低维护和安全误用风险。
  • 保留 Maven/JAR 构建作为当前明确可验证的服务构建入口。

Considered options

修复现有 Dockerfile 和 Kubernetes 清单

优点：短期内可以恢复本地容器部署。
缺点：需要提前决定未来框架的镜像供应链、配置、秘密、探针、存储和发布方式，而这些不属于当前范围。拒绝。

删除 Kubernetes 清单但保留根 Dockerfile

优点：保留本地镜像构建入口。
缺点：Dockerfile 同样来自沙箱时期且已经失效；保留它仍表达仓库维护镜像交付的承诺。拒绝。

完整删除临时 Docker/Kubernetes 资产

优点：源码边界清晰；不再维护失效入口；未来部署框架可以从真实需求重新设计。
缺点：仓库暂时不提供容器镜像和 Kubernetes 一键部署能力，外部使用者需要等待后续框架。接受。

Decision

  • 删除根 Dockerfile 和 k8s/mateservice-deployment.yaml。
  • 删除 modules/k8s 全目录，包括 Kustomize、minikube、kind 和 Docker Desktop 样例。
  • 删除 modules/coding-agent-cli/src/main/resources/application-k8s.yml，不保留空 Profile 或兼容占位。
  • README 不再把 Kubernetes 清单列为项目模块。
  • 保留 Maven/JAR 构建和通用 application.yml；不修改应用 API、数据库或 MateService 协议。
  • 未来 Kubernetes 框架必须通过新的设计和 ADR 定义，本次不声明任何替代部署实现。
  • 源码删除不自动删除外部镜像、容器、Kubernetes 对象或持久卷。

Intentional differences

架构变化：仓库从维护临时镜像与 Kubernetes 样例，改为只维护应用源码和 Maven/JAR 构建入口。

产品约束：在后续框架完成前，仓库不承诺 Docker 镜像或 Kubernetes 部署能力。

安全收口：删除包含个人绝对路径、固定 NodePort、root 容器和不完整配置注入的历史样例，避免被误用于生产。

Consequences

  • 正面：项目结构与当前交付范围一致，不再存在两套互相漂移的 Kubernetes 清单。
  • 正面：未来部署框架不受历史 minikube、kind、PVC 和镜像命名约束。
  • 负面：仓库暂时没有容器镜像构建和 Kubernetes 快速部署入口。
  • 兼容性：外部设置 SPRING_PROFILES_ACTIVE=k8s 不再加载原日志覆盖；部署方需要显式配置日志。
  • 运维：已有外部资源仍需按环境单独盘点和清理，Git 删除本身不产生集群侧变更。

Required validation

  • 确认源码和维护文档不再引用被删除的部署文件和命令。
  • 构建 campusclaw-agent.jar，确认通用应用资源完整。
  • 执行 CampusClaw 公司镜像同步检查，确认删除模块资源没有产生镜像漂移。
  • 校验设计文档、ADR 链接和 Git diff。
