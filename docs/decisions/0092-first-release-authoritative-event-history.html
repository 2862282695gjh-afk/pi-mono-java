ADR-0092：首版仅支持全新安装的权威事件历史

Status: Accepted · Date: 2026-09-08 · Version: 1.0.0

Context

产品当前处于第一版，没有受支持的旧 schema、旧应用版本或需要保留的存量 Session。 设计仓基线 2ee2a321 曾在“存在旧数据”的前提下要求一次迁移或兼容读取；用户已明确该前提 不适用于本次交付。

Java 基线 17f91e20 的安装 schema 已直接包含 t_session_events 和 t_session_event_projection。提交 45d7ece9 删除升级目录，并从投影表、Mapper、 仓储和测试中移除只服务迁移来源区分的 mapping_source。

Decision

首版只支持通过 resources/db/gaussdb/install/session_schema.sql 全新建立 Session schema。 产品不交付 V1 到 V2 升级 SQL、存量审核输入表、迁移校验函数、迁移回归或维护窗口运行手册，也不承诺 读取任何早于当前首版运行时写入的数据。

保留权威公共事件和精确完整性门禁。所有当前版本 Entry 都必须在同一事务写公共事件及精确 event_count；明确私有记录可以标零。GET 遇到未知类型、缺 marker 或数量不符时继续关闭失败， 不得在读取时猜测或补造事件。

考虑过的选项及取舍

  • 保留已经开发的迁移脚本。 它能处理未来假设的存量数据，但会制造首版不存在的升级承诺、发布入口和长期维护成本，因此删除。
  • 同时删除公共事件完整性表。 schema 更小，但当前版本发生部分写入或数据损坏时 GET 会静默返回半份历史，因此不采用。
  • 全新安装并保留运行时精确门禁。 与当前产品阶段一致，同时保住 POST/GET 同形和关闭失败安全边界，采用此方案。

Consequences

安装脚本是首版 schema 的唯一数据库基线，并保持破坏性重建语义。部署方不能把它当作已有环境升级工具。 代码和文档不再包含迁移表、函数、SQL 步骤或验证入口，权限脚本也只覆盖当前运行时表。

若未来第一次提出保留数据的升级需求，必须记录新的源/目标版本、数据来源、安全映射、事务和回滚证据， 再形成新的 ADR 与发布实现。ADR-0082 只保留为历史事实，不能直接恢复执行。

Validation

提交 45d7ece9 的产品与镜像差异确认升级目录和迁移来源已移除，当前事件表、投影表和 关闭失败查询保留。全新 openGauss 数据库上独立运行 Repository 46 项、原子事务 2 项和 Query 8 项， 共 56 项通过。
