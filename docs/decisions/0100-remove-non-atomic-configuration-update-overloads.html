ADR-0100：删除非原子配置更新重载

Status: Accepted · Date: 2026-09-08 · Version: 1.0.0

Context

Java 基线 48aac44a 的 RuntimeSessionRepository 同时公开两组 updateModel/updateThinking。新端口在一个事务中写配置状态、Entry、权威公共事件和 精确投影标记；旧六参端口把空事件工厂传入 MyBatis 实现，可以只写配置 Entry。

调用扫描发现三个生产消费者已全部使用新端口： RuntimeSessionModelReconciler、SessionModelConfigurationService 和 SessionThinkingConfigurationService。旧端口没有生产消费者，只剩 12 处模块测试调用。 当前产品是第一版，没有保留该内部端口的兼容要求。

Decision

删除 RuntimeSessionRepository 和 MyBatisRuntimeSessionRepository 中不带公共事件工厂的配置更新重载。唯一端口在获取 Session 行锁和修改数据前检查 eventFactory 非空；appendConfigurationEntries 对每个定稿 Entry 必然写权威公共事件和精确标记。

原有 12 处仓储测试调用改用真实 RuntimeCommittedEventFactory。需要配置 Entry 的场景同时改用 RuntimeEntryCodec 生成契约完整的模型或 Thinking payload，以保留原有并发、回滚、压缩观察和 Usage 快照语义。

考虑过的选项及取舍

  • 保留旧重载作为内部兼容层。 测试调用无需修改，但生产代码仍能绕过权威事件和完整性标记，与首版安全边界冲突，不采用。
  • 保留一个重载并内部自动构造事件。 Repository 缺少请求语言和已安全定稿的公开字段，猜测 payload 会复制投影规则，不采用。
  • 只保留强制事件工厂的原子端口。 编译期要求调用者选择公开事件构造规则，运行时再拒绝空工厂，采用此方案。

Consequences

配置 Entry 不再有合法的仓储路径跳过 t_session_events 和 t_session_event_projection。事件工厂构造、主键、入库或标记写入任一失败，仍由同一 Spring 事务回滚配置状态、Entry、序号和公共投影。

本决策只收敛 Java 内部仓储端口，不改变 Events、配置 HTTP 或 Builtin Command 契约，不修改 slash command 分派，也不新增 Maven 依赖。镜像代码由标准生成流程同步。

源码证据

Java 实现路径为 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/persistence/RuntimeSessionRepository.java#updateModel、 #updateThinking 和 MyBatisRuntimeSessionRepository.java#appendConfigurationEntries；实现提交为 bfaedc7e。契约基线为 pi-mono-java-design@2ee2a321。pi 基线 5cd93f68 的 packages/agent/src/agent-loop.ts#runAgentLoop 和 #prepareToolCall 没有 CampusClaw 配置资源或数据库仓储端口；本决策是 Java 架构收敛。

Validation

配置 Service、自动校准和 Command 快照单元测试 19 项通过。全新安装 schema 的真实 openGauss 上，Repository 49 项、压缩准入 11 项、压缩 Service 9 项和 Usage 10 项，共 79 项通过。Spotless、Checkstyle 和 git diff --check 通过。
