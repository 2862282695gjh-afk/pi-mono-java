ADR-0038：关闭 Mate 管理 Web 面并保留端点基础设施

Observed sourcemate-campusclaw/src/main/resources/application.properties、mate-campusclaw/pom.xml、scripts/sync-mate-campusclaw.sh

本决策中关于冗余管理上下文保护和原排除清单整体保留的部分已由 ADR-0040 替代；恢复 EndpointAutoConfiguration 公共基础 Bean 的结论继续有效。

Context

公司父 POM 会向 mate-campusclaw 传递引入 Actuator；父 POM 源码和最终公司 Classpath 不在本仓库，这一条件来自外部集成环境。变更前的公司专用配置已经默认禁用 Endpoint，并维护 30 项 Actuator 自动配置排除，但没有设置负数管理端口，也没有排除通用及 Servlet 管理上下文自动配置。

最初方案保留全部历史排除项并追加管理 Web 配置。公司环境启动验证随后出现 NoSuchBeanDefinitionException: ParameterValueMapper：Spring Boot 3.4.1 的 EndpointAutoConfiguration.endpointOperationParameterMapper 提供该公共 Bean，而公司环境中仍启用的 Actuator 配置需要注入它。由此证明历史清单中的 EndpointAutoConfiguration 排除会破坏自动配置依赖完整性。

本次目标是关闭管理 Web 面，同时保留 Actuator 公共端点基础设施。其余历史排除项继续承载公司兼容约束，不用更短的 3 项清单整体替换。

Decision drivers

  • 保留 Actuator 自动配置依赖所需的公共端点基础设施。
  • 显式关闭独立管理服务器及管理 Web 上下文。
  • 保留业务 server.port 和 HTTP/SSE 路由。
  • 把公司环境差异限定在手工维护的镜像配置。

Considered options

用 3 项管理 Web 排除替换原清单

优点：配置明显更短。
缺点：会恢复健康检查、指标、审计、缓存等 29 项原有排除，扩大变更范围且无法在当前仓库验证公司兼容性。拒绝。

只增加 management.server.port=-1

优点：改动最少。
缺点：没有显式隔离通用和 Servlet 管理上下文自动配置，未完整落实给定配置。拒绝。

保留全部原清单并追加缺失项

优点：不放宽任何历史排除边界。
缺点：排除 EndpointAutoConfiguration 后缺少 ParameterValueMapper，公司环境启动失败。拒绝。

恢复端点基础配置并保留管理 Web 排除

优点：恢复 ParameterValueMapper 等公共基础 Bean，同时继续关闭管理端口、Endpoint 默认值和管理 Web 上下文。
缺点：会实例化少量 Actuator 公共基础设施 Bean。接受。

Decision

  • 在公司专用 application.properties 增加 management.server.port=-1。
  • 保留 management.endpoints.enabled-by-default=false 和其余原有排除项。
  • 删除 EndpointAutoConfiguration 排除，让 Spring Boot 提供 ParameterValueMapper 等公共基础 Bean。
  • 保留已有的 WebEndpointAutoConfiguration，不重复声明。
  • 在原列表末尾追加 ManagementContextAutoConfiguration 与 ServletManagementContextAutoConfiguration。
  • 新增公司镜像专用测试，加载真实配置，验证关键管理 Web 排除项，并断言不排除 EndpointAutoConfiguration；同步脚本必须保留该测试。

Intentional difference

公司集成约束：通用模块不应用这些 Actuator 属性，只有公司镜像针对父 POM 传递依赖关闭管理面并保留父环境所需的端点基础设施。安全加固：管理 HTTP 服务和管理 Web 上下文被显式关闭。架构修正：基础 Bean 与管理 Web 暴露分离，业务 Servlet Web 服务继续使用 server.* 配置。

Consequences

  • 正面：ParameterValueMapper 等公共基础 Bean 可供公司 Actuator 自动配置注入。
  • 正面：管理端口和两类管理上下文都有明确关闭配置。
  • 负面：会创建 Actuator 公共端点基础设施 Bean，但不会因此开放管理 HTTP 面。
  • 负面：自动配置排除清单仍较长，Spring Boot 升级时需要检查类名变化。
  • 边界：本仓测试验证配置加载；公司父 POM 下的最终启动仍需公司工程验证。
  • 边界：公司环境已验证恢复基础配置后可以启动；本决策不改变 Log4j2 统一运行时，也不新增 Windows 支持承诺。

Validation

  • 配置加载测试断言管理端口为 -1、Endpoint 默认禁用、包含 3 个关键管理 Web 排除项，并且不排除 EndpointAutoConfiguration。
  • 执行 mate-campusclaw 完整 Maven verify。
  • 执行镜像同步 dry-run，确认公司专用配置和测试不会被覆盖或删除。
  • 检查可执行 JAR 内的配置，并执行 Git 与文档静态校验。
