ADR-0097：把持久控制信号分发到原执行实例

Status: Accepted · Date: 2026-09-08 · Version: 1.0.0

Context

Events v2 控制请求可由其他服务实例受理，但 Agent、原凭据和 pending Tool Call 只存在于原执行实例。轮询基础只认识固定 target 和持久信号，不应依赖进程内 Holder 结构。

Decision

实现窄 RuntimeLocalControlDispatcher 适配器。轮询器获取有界活动 target 并提交 stop 或 confirmation；适配器在 Session 操作锁内校验完整 target，再中止原 Agent或对原 pending future 单次 claim、恢复和 ack。确认续跑输出必须在完成 future 前绑定到新段，原凭据始终留在 Holder。

考虑过的选项及取舍

  • 让轮询器直接访问 Registry 和 Holder：代码较少，但把数据库调度、Agent 状态和凭据生命周期耦合，因此不采用。
  • 在受理实例重建 Agent：可避开本机路由，但无法保证原上下文、工具状态和凭据一致，因此不采用。
  • 只按 Session 当前执行分发：查询简单，但迟到控制可能作用于下一轮执行，因此不采用。
  • 选择固定 target 与窄接口，代价是需要本机注册表持续保留未提交终态的 Holder。

Consequences

跨实例控制最终到达实际执行进程；停止先设置取消信号再解除确认等待，确认决定至多消费一次。无匹配 Holder 或短暂失败返回 false，由轮询退避后重试。数据库不保存凭据。该片不启用 HTTP，也不新增 Maven 依赖。

Validation

实现提交 6a66f5b8 的 Dispatcher 与 Registry 直接测试 5 项通过；权限策略引入后的 Compaction 回归 41 项通过，夹具修复为 af0f69cc；AgentRuntimeManagerTest 46 项通过，347ee34a 精确断言发布与缓存恢复后的受管工具仍为 ASK、未知工具为 DENY。后两组验证共享 Registry 和可信权限边界，不计为 Dispatcher 功能用例。
