Context

源码基线把模块侧完整 db/gaussdb 树作为资源白名单同步到公司镜像，其中包含安装 DDL、空初始化数据、授权占位和 upgrade README。它们位于 src/main/resources，会进入 classpath 和公司 JAR。

公司交付要求数据库脚本位于 campusclaw/scripts/install，并且该目录只包含 initdb_gaussdbv5.sql。模块侧现有文件仍被本地开发脚本使用，不能因公司打包约束而破坏独立工程流程。

Decision drivers

  • 公司 JAR 不得包含 GaussDB 发布脚本。
  • 公司安装目录只交付一个固定名称的完整 DDL。
  • 模块侧开发与发布材料保持兼容。
  • 公司文件必须自动跟随规范 Schema，不能形成手工维护副本。
  • 同步 dry-run、pre-push 与 CI 必须能发现路径或内容漂移。

Considered options

模块侧和公司镜像同时迁移为单文件

优点：两个工程目录完全一致。
缺点：会修改 start-dev.sh 依赖的开发入口，并删除模块侧授权与升级材料，把公司交付约束扩大到独立工程。拒绝。

在公司目录手工维护独立 SQL

优点：同步脚本无需特殊转换。
缺点：同一 Schema 出现两个可编辑来源，后续表结构变化可能只更新一侧。拒绝。

由同步脚本从规范 DDL 生成公司单文件

优点：保留单一 Schema 来源，同时满足公司目录、文件名与 classpath 边界；现有镜像一致性门禁可继续工作。
缺点：同步不再是完全对称的目录复制，需要显式维护一条公司资产转换。接受。

Decision

  • 保留模块侧 src/main/resources/db/gaussdb 及 start-dev.sh 行为。
  • 同步脚本将规范 session_schema.sql 字节级复制为 campusclaw/scripts/install/initdb_gaussdbv5.sql。
  • campusclaw/scripts/install 是生成目录，通过删除同步保证只存在目标文件。
  • 公司镜像删除 src/main/resources/db/gaussdb，不交付空初始化数据、授权占位或 upgrade README。
  • --skip-resources 只跳过 classpath 资源；公司安装 SQL 始终参与镜像同步。
  • pre-push 识别文件更新与旧目录删除，CI 回归验证目录唯一性和 SQL 字节一致性。

Intentional difference

产品约束：公司镜像使用固定安装目录和单一文件名，不把数据库发布材料打入 classpath。架构变化：镜像同步从目录直拷贝调整为由模块规范 DDL 生成公司专用交付物。SQL 内容和数据库 Schema 不变。

Consequences

  • 正面：公司 JAR 不再携带数据库初始化或升级材料。
  • 正面：公司安装脚本与模块规范 DDL 自动保持一致。
  • 正面：模块侧开发脚本和多文件发布材料不受影响。
  • 代价：公司交付不再包含独立授权脚本；权限配置由外部部署流程负责。
  • 边界：目标 DDL 仍具有规范源声明的破坏性重建语义，只用于全新初始化。

Validation

  • 验证镜像和暂存区都不存在 classpath GaussDB 目录。
  • 验证公司安装目录只有目标文件，且与规范 DDL 字节级一致。
  • 执行同步、dry-run、pre-push 解析回归、Bash 语法检查和 ShellCheck。
  • 执行公司 Maven package 并确认 JAR 不含 GaussDB SQL。
  • 执行主仓 Maven verify、PlantUML/SVG/XML、文档链接和 Git diff 检查。
