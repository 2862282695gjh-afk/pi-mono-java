ADR-0075：持久化固定执行与结果段身份

Status: Accepted · Date: 2026-09-08 · Version: 1.3.0

Context

设计仓 2ee2a3211da68ad87b0d9cab353e691b00bdaebd 已确认：中断和工具确认必须绑定原始 user.message.eventId 与不可复用的内部执行身份；每次初始响应或确认续跑使用固定结果段。 Java 基线 fd556dce3cfa12e5e834b6e9b8f835f10e7d67c8 只在当前 JVM 的 RuntimeActiveExecution 保存 runId，其他实例无法参与事务校验或读取段结果。

pi 基线 4af9d21d3b4d664e4a29fcabfec85171077248e3 的 Agent Loop 接受本地 AbortSignal，但不拥有 CampusClaw 的数据库和 HTTP 生命周期。跨实例固定身份属于本项目架构变化。

Decision 与选项

  • 固定执行由根执行表、结果段表、段内完整事件关联表组成，确认决定另存一表。根执行保存内部 executionId 和公开 rootEventId；段保存触发事件与唯一结束事件；关联表保存 eventId 和统一顺序。
  • 采用 Session 行锁后再锁执行行的固定顺序；状态迁移同时校验 sessionId、executionId、rootEventId 和当前 segmentId。
  • 用 RuntimeExecutionPersistenceService 的 Spring 外层事务组合 Session Entry、公共完整事件、 执行状态与段事件关联。进入 confirming 和真实终态均先锁定精确 target，再调用短写入回调。
  • 工具确认受理在同一事务写公共回执、新续跑段和 PENDING 决定；原执行实例只能 claim 一次，处理结束后 ack。 确认与中断都先锁 Session 再锁执行，已经提交的停止状态优先并阻止确认受理或 claim。
  • 中断回执不关联原消息结果段；进入 confirming 的 tool call 与 idle 关联当前段。这样各 HTTP 响应只补读自己所属段的事件。
  • 普通完整输出仅能追加到同一 Session 下当前 RUNNING/STOPPING 执行的 OPEN 段，Entry、可选用量、公共事件、完整性标记和段关联同事务提交。
  • 相同执行、段、终态 ID 和原因的重试恢复原始终态，不再次分配序号或更新 Session；查询按真实终态与段事件关联定位，保留 confirming 段的首个 idle，也不受后续新执行状态影响。
  • 不采用仅有 sessionId + stop=true 的记录，因为迟到控制会重新选中下一轮执行。
  • 不采用只保存在 JVM 的 executionId，因为负载均衡后的请求可能由另一实例接受。
  • 不把 executionId 或 segmentId 暴露到 HTTP；公共关联继续使用已经确认的 eventId。

Tool Call ID 使用 TEXT，保留提供商原值。状态与结束原因由 Java enum 表达；数据库 CHECK 约束状态取值，以及终态和确认 claim/ack 所需字段的完整性。 第四张控制表保存确认事件、前后段、allow/deny 和一次消费状态。Session 完整清理会删除全部控制表记录，tombstone 保留既有语义。 发布权限模板同时授予运行角色新增表的 CRUD 权限，避免仅用表所有者测试而遗漏实际部署权限。

Consequences

正面：消息和控制受理、进入确认、确认决定、普通段输出和真实终态都能把公开事件与固定执行状态作为一个提交单元； 终态重试恢复原始事件而不影响下一轮执行，停止与确认竞态通过同一锁序确定。 负面：每个完整段事件增加关联写入，每个确认增加决定和新段写入，应用服务必须保持固定锁序。

本片尚未把 HTTP 路由切换到新事务，也未实现确认 HTTP、执行协调器后台终态重试调度、 批量轮询、本地唤醒和有界等待；因此本 ADR 不宣称 Events v2 控制接口已经可用。

不新增 Maven 依赖、Redis、实例间 HTTP 转发或凭据持久化。

Validation

真实 openGauss 验证登记、精确读取、confirming 关段、确认 accept/claim/ack、停止优先、终态 CAS、 300 字符 Tool Call ID，以及 Session 清理后四张控制表归零。确认基础片 Repository 回归36项通过且零跳过； 覆盖确认写入失败整体回滚、重复 claim/ack、确认与中断的行锁串行化。非所有者角色经发布模板授权验证新增表 CRUD 权限。 合并恢复与段追加主线后，Repository 42项与公共事件原子事务2项共44项通过，零跳过。格式、编译和映射检查结果记录在关联设计中。

恢复与段追加独立复验共41项真实数据库测试通过，覆盖跨Session输入、关联失败回滚、STOPPING输出、confirming后真实终态恢复、旧终态重试不结束新执行。
