Context

源码基线按提交分别执行 2000 行非文档新增代码门禁。两个各新增 1500 行的提交都合规，因此一个最终新增 3000 行的 PR 仍能进入评审。该行为与“整个 PR 新增代码不得超过 2000 行”的产品约束不一致。

门禁需要约束评审者最终看到的 PR 差异，排除目标分支在开发期间新增的内容，并保留文档排除、跨路径重命名防绕过和 Git 数据读取失败时关闭门禁的安全属性。

Decision drivers

  • 整个 PR 共享一个 2000 行新增代码额度，拆分提交不能增加额度。
  • 统计最终送审内容，不累计已经在后续提交删除或改写的瞬态内容。
  • 删除行不抵扣新增行，文档不消耗代码行额度。
  • 目标分支前进或被合并进主题分支时，不重复计算目标历史。
  • 算法可本地复现，并在 Git 输入不可读时失败关闭。

Considered options

继续按每个提交分别限制

优点：能控制单个可回滚提交的规模，并已经实现完整合并提交处理。
缺点：拆分提交即可使 PR 总新增量超过 2000 行，不能满足 PR 级产品约束。拒绝。

累计 PR 历史中每个提交的 additions

优点：拆分提交不会绕过总量限制。
缺点：同一内容的多次修改会重复计费，已经在最终 head 删除的瞬态内容仍占额度，结果不等于评审者看到的 PR 差异。拒绝。

统计 merge-base 到 head 的最终 numstat

优点：直接对应最终 PR 评审面；共同祖先排除目标分支历史；单次 Git diff 能覆盖普通提交、合并提交和冲突解决；实现更简单、开销更低。
缺点：中间曾出现但最终删除的超大内容不计入；二进制文件没有文本行数。接受。

Decision

  • 保留 scripts/check-commit-additions.sh 的 base/head 参数和 2000 行边界，以 git merge-base 计算 PR 比较基线。
  • 不再枚举提交。对 merge-base 与 head 执行一次 rename-aware git diff --numstat -z -M --no-ext-diff --no-textconv，汇总最终非文档文本路径的 additions。
  • deletions 不抵扣 additions；中间提交已经删除、未进入最终 head 的内容不属于最终 PR 差异。
  • rename 同时保留旧、新路径；文档移入代码目录时按 head 中目标 Blob 的完整文本行数统计。
  • 文档目录、文档扩展名及标准仓库文档文件继续排除；二进制内容继续由其他规则和评审约束。
  • Git revision、merge-base、最终 diff、目标 Blob 或 numstat 记录不可读时返回执行错误 2，不把失败当作 0 行。
  • CI 步骤名称更新为 PR 新增行门禁，并在既有 Spotless/Maven 门禁前运行脚本及回归测试。

Intentional difference

产品约束：2000 行从单个提交额度调整为整个 PR 的共享额度。架构变化：CI 从遍历提交历史及重建合并提交，改为只验证共同祖先到 head 的最终树差异。文档排除规则保持不变。

Consequences

  • 正面：多个小提交的最终新增代码会合并计费，不能通过拆分提交绕过限制。
  • 正面：结果与 PR 最终评审面一致，目标分支历史不会被重复计费。
  • 正面：不再需要逐提交父解析、remerge-diff 或 octopus merge 特判，算法和输出更简单。
  • 正面：文档移入代码目录和 Git 读取失败的既有防绕过能力保留。
  • 代价：提交历史中的瞬态大改动不计入，只约束最终评审差异。
  • 代价：GitHub Actions 仍需完整历史以可靠求共同祖先。
  • 边界：二进制文件没有文本新增行；其大小和适用性继续由其他规则及评审约束。

Validation

  • 用临时 Git 仓库覆盖 2000/2001 边界、多个提交累计 3000 行、最终缩减到 1000 行和文档排除。
  • 覆盖 code-to-code、docs-to-code 重命名，目标分支同步、merge-only 内容、冲突解决和不可读 Git Tree。
  • 执行 Bash 语法检查、ShellCheck、脚本回归测试和当前 PR 范围门禁。
  • 执行 Maven verify、Git diff 检查及设计文档、PlantUML、SVG 验证。
