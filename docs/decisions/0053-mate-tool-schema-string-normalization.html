ADR-0053：网关工具 schema 字符串形态归一化与非法降级策略

StatusAccepted
Date2026-09-05
DecidersRuntime / Mate 工具链评审
Related设计文档 docs/designs/mate-tool-schema-parsing.md；TOOL元数据设计.json（Mate 侧元数据草案）；PR #226

Context

实测网关 tools/query 将 input_schema / output_schema 以序列化 JSON 字符串返回 （"{\"type\":\"object\",...}"），且存在驼峰键 inputSchema 变体。ToolInfo 将两字段声明为 Map<String,Object>——字符串→Map 绑定失败被 Jackson 静默置 null，或驼峰键被未知键策略忽略。

连锁后果：ListMateTools 传给模型的 inputSchema 为空对象 {}， 模型不知道工具参数结构，CallMateTool 的 args 随机生成。 既有单测的夹具恰好写的是对象形态，未暴露该问题。

Decision

  1. 宽容反序列化：新增 SchemaMapDeserializer 挂接 ToolInfo 两个 schema 字段； 字符串形态二次反序列化，对象形态直接归一化；@JsonAlias 兼容驼峰键变体。
  2. 非法降级为 null：字符串不是合法 JSON 对象时归一为 null 并 log.warn， 不抛异常、不阻断整批元数据解析。上游（ListMateToolsTool）对 null 有既有兜底 （序列化为空对象 {}），模型收到空结构。
  3. 缓存不动：MateToolSessionCache 仅缓存 name→toolId 映射，schema 不进缓存； Mate 侧 schema 填实后 ListMateTools（实时查询）下一次即生效。

考虑过的选项

选项ProCon
A. 双形态归一化 + null 降级（选定）单工具坏数据不阻断整批（可用性优先）；实现集中在 DTO 反序列化器降级后该工具参数结构对模型不可见，args 只能猜测
B. 非法 schema 抛异常快速暴露数据问题单个坏 schema 阻断整批发现，所有工具不可用——可用性损失远大于收益
C. 原始字符串透传给模型信息"无损"模型收到无法解析的转义字符串比空结构更糟，可能把字符串当参数值回填

选择 A：可用性优先 + 降级路径可观测（log.warn），根治依赖 Mate 注册侧填实参数定义。

Consequences

  • 正向：schema 字符串/对象双形态即插即用；单点数据损坏不影响其他工具的发现与调用。
  • 正向：完全向后兼容——对象形态行为不变，现有对象形态夹具保持通过。
  • 负向：非法 schema 降级后该工具对模型"参数不可见"（args 猜测），依赖 log.warn 监控发现频率。
  • 后续：Mate 注册侧填实参数定义后，降级路径几乎不会命中；若 input_schema 位置标注 （x-mcp-in）提案落地，schema 内容将扩展参数位置语义，反序列化器无需变更（透传 Map）。

验证

HttpMateToolClientTest 32/32 通过，含新增： stringEncodedSchemaWithCamelCaseKeysIsNormalized（驼峰键 + 字符串形态）、 malformedSchemaStringDegradesToNullInsteadOfFailingBatch（非法降级）、 snakeCaseStringSchemaPreservesNestedConstraints（snake 主键 + required 保留）、 mixedBatchWithInvalidSchemaIsolatesDamagePerTool（混合批次按工具隔离损伤）。 全模块 676+ tests 通过；campusclaw/ 镜像同步（dry-run 内容级差异 0）。
