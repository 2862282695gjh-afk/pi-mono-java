ADR-0035：删除 CampusMate 旧部署变量兼容脚本

StatusAccepted
Date2026-08-28
Source baselineorigin/main@28b3235e5cff0da2f768cbfc6b7b9ce5e2b51193
Observed sourcecampusclaw/scripts/install_value.sh、campusclaw/src/main/resources/application.properties、modules/coding-agent-cli/src/main/resources/application.yml、scripts/sync-campusclaw-exclude.txt

Context

campusclaw/scripts/install_value.sh 是公司镜像侧独有的部署适配脚本。它读取 /etc/profile，把旧平台变量 CAMPUSINNERGWSERVICE_DOMAIN_NAME_URL 转换为应用实际读取的 CAMPUSMATE_BASE_URL。四个主模块没有对应脚本，主模块 YAML 和公司镜像侧 properties 都已经只读取 CAMPUSMATE_BASE_URL。

部署不再需要兼容旧变量后，保留脚本会继续暗示两套受支持的配置入口，并使新部署误以为必须先 source 一个安装脚本。实际应用只需要启动进程环境中的一个明确变量。

Decision drivers

  • 让部署入口与应用配置契约一致，只保留 CAMPUSMATE_BASE_URL。
  • 移除主模块不存在、仅由公司镜像手工维护的兼容资产。
  • 避免首次部署把环境变量适配脚本误解为安装或启动程序。

Considered options

保留现有兼容脚本

优点：仍使用旧变量的部署无需调整。
缺点：继续维护已明确不需要的双入口，并增加部署认知成本。拒绝。

把旧变量回退逻辑移入 Java 应用

优点：不再依赖 Shell。
缺点：把已放弃的兼容契约扩散到所有主模块运行方式，并引入变量优先级。拒绝。

只接受新变量

优点：部署契约与应用读取路径完全一致，不需要额外脚本。
缺点：仍使用旧变量的外部部署必须迁移。接受。

Decision

  • 删除 campusclaw/scripts/install_value.sh。
  • 删除 scripts/sync-campusclaw-exclude.txt 中对该公司镜像侧目录的登记。
  • 部署必须直接向 CampusClaw 进程提供非空 CAMPUSMATE_BASE_URL。
  • 仓库不读取或转换 CAMPUSINNERGWSERVICE_DOMAIN_NAME_URL，也不增加应用内旧变量回退。
  • 本决策仅废止 ADR-0026 的安装脚本兼容条款；共享 base URL、Endpoint 目录和校验决策继续有效。

Intentional difference

产品约束：旧部署变量不再属于支持的安装输入。架构变化：部署边界从“旧变量经 mate 专用 Shell 转换”收敛为“启动进程直接接收应用变量”。CampusMate HTTP 契约不变。

Consequences

  • 正面：主模块与公司镜像使用同一个明确的环境变量契约。
  • 正面：首次安装无需理解或执行额外的变量转换脚本。
  • 负面：仍只设置旧变量的外部部署在迁移前将因缺少必填配置而启动失败。
  • 后续：外部 mate 父工程和部署流水线若曾调用该脚本，必须移除调用并直接注入新变量。

Validation

  • 排除历史设计记录后，交付文件和实现配置搜索不再出现脚本名或旧部署变量。
  • 镜像同步 dry-run 证明主模块与公司镜像源码仍然一致。
  • git diff --check 验证删除和文档更新没有格式错误。
