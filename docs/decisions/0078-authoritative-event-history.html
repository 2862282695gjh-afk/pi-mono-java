ADR-0078：权威事件历史与精确完整性

Status: Accepted · Date: 2026-09-08 · Version: 2.0.0

Context

Events v2 要求 GET 与 POST 复用完整公共事件。内部 Entry 同时承担模型上下文恢复， 无法单独证明一对多公共事件是否写全，也不适合在 GET 时临时生成公开身份、关联和文本。

当前产品是第一版，没有受支持的旧安装或存量数据。早期版本把旧历史迁移列为本决策的一部分； ADR-0092 已按首版产品范围取代这部分， 权威公共表和当前版本完整性门禁仍保持有效。

Decision

使用 t_session_events 保存一次稳定公共事件，并以 t_session_event_projection 的每 Entry 精确数量证明投影完整。运行时通过组合仓储在同一事务写 Entry、Usage、 公共事件、标记和序号。GET 在单个 REPEATABLE_READ 事务内核验当前分支后按普通整数页读取， 再由唯一严格投影器产生只读 VO。

全新安装 schema 直接创建两张表。完整性标记只表示当前运行时已经完成该 Entry 的公共投影，不携带迁移来源。 未知内部类型、缺少标记、实际数量不符、公开必需类型为零或明确私有类型为正数时，GET 关闭失败。

选项与取舍

  • 权威公共表使 POST 与 GET 逐字段一致，也支持一条 Entry 映射多条事件；代价是每次写入增加事件和完整性记录。
  • 查询时动态转换内部 Entry 无需公共表，但不能稳定证明身份、安全字段和一对多完整性，因此不采用。
  • 只检查“至少一条公共记录”无法发现 Assistant 工具调用遗漏；精确数量标记增加一次写入，却能拒绝半份历史。
  • 完全取消完整性标记可以简化首版 schema，但会把当前版本的部分事务写入暴露为合法历史，因此不采用。

Consequences

公开事件写入锁序固定为 Session、execution、sequence、Entry/Usage、公共事件、完整性标记、控制关联。 合法 completed Thinking 可在写入时根据可信摘要标零或标正数；tool.execution.started 不能标零掩盖 缺失工具调用。查询不修补损坏数据，也不返回半份结果。

首版只支持全新安装。升级脚本、迁移审核表、校验函数和迁移来源字段不进入产品；未来若首次提出保留数据的升级， 需要基于当时的 schema 和安全证据重新决策。

Validation

单元与真实 openGauss 测试覆盖数字分页、当前分支、精确数量、未知类型、Thinking 双分类、工具调用缺口、 原子回滚和 UTC 毫秒一致。首版清理基线 17f91e20 在全新数据库独立运行 Repository 46 项、原子事务 2 项、 Query 8 项，共 56 项通过；升级目录及 mapping_source 已删除，运行时权威事件与门禁保留。
