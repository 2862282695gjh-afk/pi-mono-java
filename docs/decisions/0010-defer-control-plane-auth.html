ADR-0010 · 控制面端点鉴权延期

Status: Deferred · Date: 2026-06-22 · 设计文档: control-plane

Context

控制面 HTTP 端点（/api/v1/nodes/*、/api/v1/runtimes/*）当前对任何能访问该端口的调用方开放——无认证、无授权、无 TLS。

ServerMode 默认绑定 localhost，在单机开发 / 本地部署场景下风险有限。但作为 "control plane"，一旦暴露到网络（0.0.0.0 绑定 / Kubernetes Service / 反向代理），任何客户端都能注册恶意节点、篡改心跳、触发调度。

Options considered

  • Spring Security + bearer token — 适用但引入完整 Spring Security 依赖链（12+ MB），对 CLI 工具偏重；当前只有 7 个端点，over-engineering。
  • mTLS（双向 TLS） — 运维成本高（证书签发 / 轮换 / 分发），适合 K8s 生产部署，不适合本地开发。
  • 简单 bearer token（HandlerFilterFunction 校验） — 最轻量：加一个 Authorization header filter，token 从 application.yml 读。适合 v1。但当前无需求驱动（没有非 localhost 部署），过早加锁增加测试复杂度。
  • 暂不实现，显式记录为 deferred (chosen) — 当前 localhost 绑定风险可控；等真正需要网络暴露时再实现。

Decision

  • 控制面鉴权（mTLS / bearer token / Spring Security）**暂缓实现**，登记在 DEFERRED.md DEF-004
  • ServerMode 默认绑定 localhost，不暴露到网络
  • 当需要 0.0.0.0 绑定或 Kubernetes 部署时，必须先实现鉴权再暴露端口
  • 鉴权实现时优先选 简单 bearer token + HandlerFilterFunction，避免引入 Spring Security 全量依赖

Consequences

  • 正面: v1 不增加部署复杂度；localhost 场景无额外配置
  • 负面: 端口误暴露（--host 0.0.0.0）时无防护——需在文档 / runbook 中明确警示
  • 后续: 鉴权上线时本 ADR Status 改 Superseded，新建 ADR 记录所选方案
