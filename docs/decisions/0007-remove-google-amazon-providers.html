ADR-0007 · 精简 AI 模块：移除 Google（Generative AI / Vertex）与 Amazon Bedrock provider

Status: Accepted · Date: 2026-06-29 · 设计文档: ai

Context

modules/ai 是 CampusClaw 的 LLM 多供应商抽象层。它原生实现了 Anthropic、OpenAI（Responses / Completions）、Google（Generative AI 与 Vertex）、Amazon Bedrock、Mistral 等 provider，外加约 18 个 OpenAI 兼容 flavor。Google 与 Amazon 两条线带来了不成比例的维护负担：

  • google-cloud-aiplatform 被声明为 modules/ai/pom.xml 依赖，但整个代码库从未 import——两个 Google provider 实际只用 JDK 自带的 java.net.http.HttpClient，该依赖是纯粹的死重量；
  • software.amazon.awssdk:bedrockruntime 是一套庞大的原生 SDK，仅被 BedrockProvider 一个类使用，且 Bedrock 在内置模型目录里没有任何 built-in 模型；
  • 这两条线还牵动凭据嗅探（Google ADC、AWS 多凭据源经 <authenticated> 哨兵）、控制面能力枚举（RuntimeCapability.MODEL_GOOGLE / MODEL_BEDROCK）、文档、以及 campusclaw 镜像，维护面广。

目标是把 provider/模型/凭据/依赖面收敛，降低维护与镜像成本。

Options considered

  • 保留枚举值、仅删实现（删除 *Provider 类与 SDK，但保留 Provider.GOOGLE 等枚举与内置模型）——拒绝：留下无实现的「死枚举」与无法路由的内置模型，反而更易误导，不算「精简」。
  • 仅删 Amazon、保留 Google——拒绝：Google 同样是未使用 SDK + 高维护面，且用户明确要求两者一并移除。
  • 全量移除（选定）——删除两类 provider 的实现、内置模型、SDK 依赖，以及 Provider / Api / RuntimeCapability 上的相关枚举值、EnvApiKeyResolver 的凭据分支，并清理所有下游消费者、文档与镜像。

Decision

  • 删除 provider/google/（GoogleGenerativeAIProvider、GoogleVertexAIProvider、GoogleShared）与 provider/bedrock/BedrockProvider 及其单测；
  • ModelRegistry 移除 googleGenerativeAiModels() / googleVertexAiModels() 内置表，以及唯一一条经 OpenRouter 透出的 google/gemini-2.5-pro 条目——内置目录里不再出现任何 Gemini；
  • Provider 删除 GOOGLE / GOOGLE_VERTEX / AMAZON_BEDROCK / GOOGLE_GEMINI_CLI / GOOGLE_ANTIGRAVITY；Api 删除 BEDROCK_CONVERSE_STREAM / GOOGLE_GENERATIVE_AI / GOOGLE_VERTEX / GOOGLE_GEMINI_CLI；
  • EnvApiKeyResolver 删除对应 case 与 detectGoogleADC() / detectBedrockCredentials()；<authenticated> 哨兵随之退场（此前仅这两类 provider 使用）；
  • modules/ai/pom.xml 与根 pom.xml 移除 google-cloud-aiplatform、software.amazon.awssdk:bedrockruntime 依赖、版本属性与 dependencyManagement 条目；
  • 控制面 RuntimeCapability 删除 MODEL_GOOGLE / MODEL_BEDROCK；同步更新 CLI 帮助文案、Diagnostics 的 GOOGLE_API_KEY 行及相关单测；
  • 新增 SupportedProvidersDocTest：从 ModelRegistry.builtInModels() 反推「有内置模型的 provider 集合」，与 README.md 中隐藏的 BEGIN/END supported-providers 规范 id 块严格比对——今后增删 provider 而忘记同步文档即 CI 变红。

Consequences

  • 正向：依赖树显著收缩（移除一套 AWS 原生 SDK + 一个未使用的 Google 依赖）；provider/凭据/枚举面更小；文档与代码由测试钉死，不再漂移。
  • 负向 / 迁移：不再支持以 Google（AI Studio / Vertex / Gemini CLI / Antigravity）或 Amazon Bedrock 为 provider 的模型；settings.json 中若有命名这些 provider 的自定义模型将无法解析（Provider.fromValue 抛错）。需要 Gemini 的用户仍可经 OpenRouter 等 OpenAI 兼容 flavor 自行配置 custom 模型。
  • 后续：campusclaw 镜像经 sync-campusclaw.sh 的 rsync --delete 自动移除镜像副本；其手维护的 pom.xml 需手动删除两条依赖。
