ADR-0008 · 控制面 HTTP 端点用 webflux RouterFunction 而非 @RestController

Status: Accepted · Date: 2026-06-18 · 设计文档: control-plane · 关联: ADR-0007

Context

CampusClaw 的 application.yml 设置 spring.main.web-application-type: none——CLI 默认不启动内嵌 web 服务器，只在 --mode server 时由 ServerMode 手动启动 reactor-netty HttpServer。

Spring Boot 的 @RestController 依赖 servlet 或 reactive web autoconfig 才能注册路由。在 web-application-type: none 下，autoconfig 不启动，@RestController bean 虽然被创建但**不会绑定到任何 HTTP 服务器**——端点静默不可达。

此外，coding-agent-cli 用的是 spring-boot-starter-webflux（reactive/Netty），如果控制面用 spring-boot-starter-web（servlet/Tomcat），两者 classpath 冲突——同一进程不能同时跑 Tomcat 和 Netty。

Options considered

  • @RestController + 改 web-application-type: reactive — rejected: 默认启动 8080 端口的 netty 服务器，interactive / one-shot 等非 server 模式也会启动 web server，资源浪费；需要额外 conditional 才能避免；servlet API 跟现有 webflux 不兼容。
  • RouterFunction + HandlerFunction（webflux 函数式） (chosen) — 跟 ServerMode 现有 chat / skill / settings 路由风格一致；RouterFunction bean 由 ServerMode.buildRoutes 合并到 reactor-netty 主链；CLI 非 server 模式不启动 web 服务器，零开销。
  • 手工 HttpHandler（无 Spring 抽象） — rejected: 放弃 Spring 的内容协商 / 异常处理 / filter 链，所有功能要手写；跟 ServerMode 已有的 RouterFunction 架构不一致。

Decision

  • 控制面 HTTP 端点用 RouterFunction<ServerResponse> 声明，注册为 Spring @Bean
  • ServerMode 通过 setExtraRoutes(List<RouterFunction>) 接收额外路由，用 .and() 合并到主 RouterFunction 链
  • CampusClawCommand 通过 ApplicationContext.getBeansOfType(RouterFunction.class) 收集所有声明式路由 bean，传给 ServerMode
  • 异常翻译用 HandlerFilterFunction（ControlPlaneExceptionHandler），不依赖 @RestControllerAdvice（servlet 专属）

Consequences

  • 正面: 跟 coding-agent-cli webflux 栈完全一致；非 server 模式零 web 开销；新路由只需加 @Bean RouterFunction 即自动合并
  • 正面: WebTestClient.bindToRouterFunction 直接测路由，无需 @SpringBootTest 启动完整 context
  • 负面: RouterFunction 不支持 jakarta.validation 自动校验——DTO 校验改用 record compact constructor 抛 IllegalArgumentException，由 ControlPlaneExceptionHandler 翻译为 400
  • 负面: getBeansOfType(RouterFunction.class) 收集面较宽——未来第三方 RouterFunction bean 可能被误合并（见 ADR-0009）
