CampusClaw 转为公司独立服务后，本决策所依赖的子模块集成前提不再成立。ADR-0043 删除了应用级 Actuator 属性和全部排除项；本文保留为旧部署拓扑下的历史决策。

Context

campusclaw 通过公司父 POM 获得 Actuator 依赖。本仓配置使用 management.server.port=-1 关闭管理 HTTP，并使用 management.endpoints.enabled-by-default=false 默认关闭 Endpoint，同时还维护 31 个显式自动配置排除。

基于 Spring Boot 3.4.5 源码逐项复核后发现，10 个 Endpoint 排除与 Endpoint 默认 access 重复，ManagementContextAutoConfiguration 与负数管理端口重复；另外有 3 个类名不在 3.4.5 自动配置清单中，其中 Elasticsearch 条目使用了错误拼写。冗余清单增加升级维护成本，也让字符串测试在类名已经失效时仍然通过。

Source evidence

  • ManagementPortType.get 在 management.server.port 为负数时返回 DISABLED。
  • ManagementContextAutoConfiguration 的内部配置只匹配 SAME 或 DIFFERENT。
  • PropertiesEndpointAccessResolver.determineDefaultAccess 把 management.endpoints.enabled-by-default=false 转换为 Access.NONE。
  • WebEndpointAutoConfiguration、ServletManagementContextAutoConfiguration、Health Contributor、Metrics 和 Observation 仍可独立创建 Bean，不属于同一关闭语义。
  • Spring Boot 3.4.5 自动配置清单包含 ElasticsearchRestHealthContributorAutoConfiguration，不包含旧 ElasticSearch...、旧 Mongo 包名或 ManagementServerAutoConfiguration。

Decision drivers

  • 一个配置项只承担一个可核对的关闭语义。
  • 不在当前场景保留冗余纵深保护。
  • 保留公司环境仍需要的 Endpoint 公共基础 Bean。
  • 继续阻止不受管理端口和 Endpoint 默认 access 控制的独立 Bean 与副作用。
  • 所有显式排除类名必须与 Spring Boot 3.4.5 自动配置清单一致。

Considered options

保留全部纵深保护

优点：单项 Endpoint 或管理端口误配置后仍有额外阻断。
缺点：同一意图由多个机制重复表达，类名会随 Spring Boot 升级漂移，并与当前“不需要冗余防护”的产品约束冲突。拒绝。

删除全部自动配置排除

优点：配置最短。
缺点：会恢复 Health Contributor、Metrics、Observation、审计和请求交换记录等独立 Bean 或副作用，超出管理 HTTP 与 Endpoint 默认 access 的关闭范围。拒绝。

删除重复项并保留独立作用项

优点：关闭语义单一，保留非重复的公司兼容边界，并清除失效类名。
缺点：如果以后主动覆盖管理端口或 Endpoint access，系统不再依靠重复排除阻止该配置生效；届时必须形成新的产品决策。接受。

Decision

  • 以 management.server.port=-1 作为关闭管理 HTTP 的唯一配置，删除 ManagementContextAutoConfiguration 排除。
  • 以 management.endpoints.enabled-by-default=false 作为默认关闭 Endpoint 的唯一配置，删除 10 个 Endpoint 自动配置排除。
  • 保留 18 个仍会独立创建 Bean 或产生副作用的自动配置排除。
  • 删除旧 Mongo 包名和不存在的 ManagementServerAutoConfiguration。
  • 把错误的 ElasticSearchRestHealthContributorAutoConfiguration 修正为 ElasticsearchRestHealthContributorAutoConfiguration。
  • 测试精确断言 18 项目标集合，不再只抽查少数字符串。

Intentional differences

产品约束：本场景不需要冗余防护，后续显式开放管理端口或 Endpoint 时由新的配置和设计决策负责。安全边界：管理 HTTP 仍由负数端口关闭，Endpoint 仍默认不可访问。架构变化：排除清单从重复表达关闭意图改为只控制独立基础设施 Bean 和副作用。

Consequences

  • 正面：排除项从 31 项收敛为 18 项，所有保留类名都存在于 Spring Boot 3.4.5 自动配置清单。
  • 正面：Endpoint 公共基础配置继续保留，避免再次缺失 ParameterValueMapper。
  • 正面：测试可以发现冗余项、失效类名或清单漂移。
  • 负面：如果更高优先级配置覆盖管理端口或 Endpoint access，系统不会再依靠重复排除抵消该覆盖。
  • 边界：公司父 POM 和最终 classpath 不在本仓，仍需公司工程执行最终启动验证。

Validation

  • 执行 ManagementConfigurationTest。
  • 执行 campusclaw Maven verify。
  • 对照 Spring Boot 3.4.5 AutoConfiguration.imports 验证保留类名。
  • 执行镜像同步 dry-run、文档链接检查和 git diff --check。
