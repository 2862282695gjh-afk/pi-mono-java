ADR-0099：原子启用统一 Events v2 HTTP

Status: Accepted · Date: 2026-09-08 · Version: 1.0.0

Context

严格联合请求、完整公共事件、消息受理、跨实例控制和结果等待已经分别实现，但前置切片都没有切换生产 Controller。若只启用其中一部分，客户端会遇到混合的旧请求字段、旧 SSE 包装和新历史事件。本产品是首次发布，不需要 V1 到 V2 的升级兼容。

Decision

在一个接入片中把 POST /sessions/{sessionId}/events 切换为三类严格事件，把 SSE 切换为 data-only 公共事件，并把同路径 GET 切换为数字分页的权威事件查询。控制回执在事务提交后入流，后续完整结果统一从数据库 waiter 交付；confirmation 本机只直推 preview。首帧前错误显式返回 JSON。同时删除旧 abort、steers、follow-ups、游标历史和无消费者的普通事件投影链，只保留仍被 Compaction 调用的专用公共投影。

考虑过的选项及取舍

  • 逐个切换请求、SSE 和 GET：发布粒度较小，但会形成客户端无法完整解释的中间契约，因此不采用。
  • 长期并行保留旧控制路由：迁移看似平滑，但产品首次发布没有旧用户，双写和旧队列会破坏唯一控制语义，因此不采用。
  • 本机确认结果直接写入响应、跨实例才补读：延迟较低，但 notify 与直推会重复完整事件，因此不采用。
  • 选择统一启用增加一次依赖集成成本，换取一个可验证、无兼容分支的首版协议。

Consequences

生产 HTTP 从本片开始启用 Events v2。三类用户事件共享一个入口，完整 SSE 与 GET 逐字段同形，旧三控制路由返回 404。首帧前错误稳定为 application/json。Compaction 仍写 session.compacted 和 exact marker，私有 summary 不公开。前端由独立任务按新契约适配。没有新增 Maven 依赖。

Validation

最终接入 hash 77348ee9 在首次发布主线上通过 141 项聚焦测试。已有集成验证基线 d9466919 的完整 Reactor 共运行 2130 项单元测试：common 17 项、ai 505 项、agent 140 项、cron 70 项、coding-agent 1398 项，全部通过且无跳过；coding-agent 统计已包含 5 项进程夹具。等价产品集成 ac19a892 另使用最新实际 JAR 和全新 openGauss 运行 29 项 Events v2 HTTP 验收，全部通过且无跳过，其中跨 JVM 场景覆盖 interrupt 与 allow。5 项进程夹具验证缓存恢复与损坏拒绝、HTTP 响应时机、关闭时阻塞响应和非 Chat 路径拒绝，不与 29 项 HTTP 验收重复相加。最终依赖合并 b6d490a1 另通过 274 项聚焦单元测试、49 项真实 Repository openGauss 测试和 20 项实际 JAR 的 Command、Skill、Compact HTTP 测试，全部无失败、错误或跳过。企业镜像已同步；公司 Maven 因企业 NativeParent 当前不可获得，未完成编译验证。
