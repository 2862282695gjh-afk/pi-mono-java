ADR-0009 · CampusClawCommand 用 getBeansOfType(RouterFunction.class) 收集路由 bean

Status: Accepted · Date: 2026-06-18 · 设计文档: control-plane · 关联: ADR-0008

Context

控制面路由（NodeRoutes / RuntimeRoutes）声明为 @Bean RouterFunction<ServerResponse>。ServerMode 是非 Spring 管理的 POJO，在 CampusClawCommand.runServerMode() 中手工 new 出来。需要一种方式把 Spring 容器里的 RouterFunction bean 传递给 ServerMode。

CampusClawCommand 是 @Component，已注入 ApplicationContext。

Options considered

  • 逐个 @Autowired RouterFunction bean — rejected: 每加一个新路由（如 RuntimeRoutes）都要改 CampusClawCommand 构造器签名 + ServerMode 参数列表，侵入性高；且 Spring 按类型注入多个同类型 bean 需要额外 @Qualifier。
  • @Autowired List<RouterFunction<ServerResponse>> — better, 但 Spring 对泛型擦除的 List 注入有时不稳定（取决于 Spring 版本和 bean 注册顺序），需要额外 @Order 才能控制合并顺序。
  • getBeansOfType(RouterFunction.class) 收集全部 (chosen) — 简洁、零侵入、新路由只需加 @Bean 自动纳入；缺点是收集面过宽（见下）。
  • 自定义 @ControlPlaneRoute 限定注解 + getBeansOfType with annotation — 最精确，但当前只有 2 个路由 bean，加注解 + 扫描逻辑的工程量不划算。推迟到路由数量增长时再引入（见 Consequences）。

Decision

  • CampusClawCommand.collectExtraRouterFunctions() 通过 applicationContext.getBeansOfType(RouterFunction.class) 收集所有 RouterFunction bean，转型后传给 ServerMode.setExtraRoutes()
  • ServerMode.buildRoutes() 用 base.and(extra) 逐个合并到主 RouterFunction 链
  • applicationContext == null 时返回空列表（测试场景兼容）

Consequences

  • 正面: 新增路由（如未来的 ManagementRoutes）只需写 @Bean RouterFunction，零改动 CampusClawCommand / ServerMode
  • 负面: getBeansOfType(RouterFunction.class) 按原始类型抓取，未来如果引入第三方 RouterFunction bean（如 springdoc-openapi 的 OpenAPI 路由），会被误合并到 ServerMode 主链
  • 缓解: 当第三方 RouterFunction bean 出现时，引入 @ControlPlaneRoute 限定注解，改 getBeansOfType 为带注解过滤——当前无第三方 bean，暂不引入
