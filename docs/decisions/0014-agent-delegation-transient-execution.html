ADR-0014 · 父 Agent 调用子 Agent 的瞬态执行链路

Status: Accepted · Date: 2026-08-18 · Amended: 2026-08-19 · 设计文档: agent-delegation · 上游: ADR-0012 · 上游设计: mainagent-subagent-design.md §5–§6

Context

ADR-0012 落地了委派的静态校验组件（AgentBindingResolver / DelegationContext / 授权与元数据端口），但 resolver 尚无调用方——模型无法实际把任务交给子 Agent。本 PR 补齐执行链路：模型调用 invoke_agent(agentId, task) 后，进程内完成候选发现 → 每跳校验 → 瞬态子会话执行 → 子回答回填父循环。上游设计要求：候选只来自父直接 bindingAgents、深度硬上限 2、每跳 validate-before-execute、子 Agent 瞬态执行不共享状态。

Options considered

  • 常驻子 Agent worker 池
    Pro：复用已初始化的会话与 SkillRegistry，单次委派延迟低。
    Con：子 Agent 状态跨调用存活，深度/ancestry 语义难以隔离；快照热更新与池内状态一致性复杂；本地 CLI 单用户场景收益小。Rejected。
  • 子 Agent 作为独立进程 / 远程服务调用
    Pro：故障隔离最强。
    Con：需要部署形态与传输协议（属后续 ToolClient/组④ 范畴）；当前阶段进程内直连即可满足。Rejected（现阶段）。
  • 进程内瞬态执行：每次调用新建 Agent/AgentState/tools，用完即弃
    Pro：无共享状态天然并发安全；深度封顶直接编码进 DelegationContext 构造不变量；与现有 AgentSession 基建零新增运行时设施。
    Con：每跳有会话构建开销（本地 prepare 走快照，毫秒级，可接受）。Chosen。

选择理由：上游设计 §6 明确 transient 执行模型；本地 CLI 试点阶段吞吐要求低，正确性与可审计性优先。

Decision

  • 组件分层：InvokeAgentTool（无状态 ControlTool，仅 ack + 候选描述装饰）→ LocalAgentDispatcher（候选解析、每跳 validate、context 构造、审计日志、prepare）→ TransientAgentRunner（瞬态会话执行、末条 AssistantMessage 提取）。
  • 执行副作用放在会话 after-tool-call 钩子（与 activate_skill 同构）：工具本体无状态可被 Spring 目录发现；真实派发由 AgentSession.handleDelegationToolCall 完成并覆盖工具结果内容。
  • 暴露三重门：delegationState != null ∧ resolver 候选非空 ∧ 本地 ToolSelection 可见；深度 2 的子会话候选恒空，自然不暴露 invoke_agent。
  • 每跳重新 validate（§5.2）：dispatcher 不信任暴露时的候选快照；Rejected 转 AgentRuntimeException → 父侧 isError 工具结果。
  • 瞬态子会话：runtimeManager.sessionConfig 令子默认模型优先、入口会话模型兜底；子 cwd = 其 agentRoot；task 即完整用户提示；子系统提示来自其物化 systemPrompt.md。
  • 审计暂为结构化英文 INFO 日志（parent/target/ancestry/depth/invocationId/conversationId）；正式审计事件流与 PendingDelegation 续接属后续 PR（组⑤）。
  • 入口接线（显式托管 CLI）：HTTP V1 架构删除旧 ServerMode/SessionPool 后，CampusClawCommand 仅在显式 cli --agent-id 已准备托管运行时且 dispatcher bean 可用时注入 DelegationState.entry(...)；bean 缺失仅降级不报错。普通 CLI 和独立 .campusagent HTTP V1 均不启用该物化链。
  • 本地元数据源：LocalChildAgentMetadataSource 本地快照优先、远程只读回退、双失败 fail closed（UNKNOWN_CHILD）。

Consequences

  • 正面：父 Agent 可按设计语义把自包含任务交给直接绑定的子 Agent，两级委派链（1→2→3 型拓扑）端到端可用；所有拒绝路径带原因回传模型可自行改道；无新增常驻线程/池。
  • 负面：每跳重建会话有毫秒级开销（可接受）；子回答提取只认末条 AssistantMessage 文本，多模态输出仅取文本部分；同步 join() 占用父循环线程——异步化与 PendingDelegation 续接（组⑤）留待后续。
  • 后续：ToolClient/权限公式收敛（组④）、审计事件流与续接（组⑤）按 roadmap 独立 PR；租户身份贯通后替换 PermitAllAgentAuthorizationPolicy。
