ADR-0016 · 仅维护 macOS/Linux 启动方式

Status: Accepted · Date: 2026-08-20 · 设计文档: platform-support · 基线: origin/main@3a6358bc9dd5837cdf5ac866fc0761298372510a

Context

基线同时维护 macOS/Linux Shell 与 Windows Batch 两套启动和安装实现，并额外分发 Windows Maven Wrapper、维护 Task Scheduler 集成及 Windows 网络排障资料。不同平台的 Shell、路径、证书库和系统调度器语义增加了每次启动相关变更的维护和验证成本。产品现阶段只需要 macOS 与 Linux 本地环境，因此需要把支持承诺、入口文件和运行时分派保持一致。

Options considered

  • 继续同时维护 macOS/Linux 与 Windows
    Pro：现有 Windows 用户无需迁移。
    Con：继续承担 Batch、PowerShell、CMD Wrapper、Task Scheduler 和平台专属网络问题的维护与验证。Rejected。
  • 文档标记 Windows 已弃用，但保留所有入口
    Pro：短期变更较小，旧命令仍可能运行。
    Con：仓库文件仍会暗示支持，入口继续腐化，后续修改仍需判断是否同步更新。Rejected。
  • 删除 Windows 启动链路并在执行入口明确限制平台
    Pro：文档、脚本和系统调度器形成单一支持边界；不支持平台快速失败。
    Con：Windows 用户无法继续使用仓库提供的启动、安装、构建或定时触发入口；没有兼容期。Chosen。

选择理由：这是明确的产品支持范围收敛。仅修改说明而保留可执行入口会继续形成隐含承诺，因此必须同步删除 Windows 文件和运行时调度分支。

Decision

  • macOS 和 Linux 是唯一受支持、受维护的本地启动与安装平台。
  • 删除 campusclaw.bat、install.bat、mvnw.cmd 和 Windows 网络排障文档。
  • campusclaw.sh 与 install.sh 仅接受 Darwin 或 Linux。
  • SystemSchedulerInstaller 只保留 macOS launchd 与 Linux crontab；其他系统明确拒绝操作，并且启动脚本检测只查找 campusclaw.sh。
  • 项目说明和代理工程规范不再提供 Windows 命令，并禁止无新决策时重新引入 Windows 启动入口。
  • 与归档输入安全或通用进程健壮性相关的既有防御不因本决策自动删除，它们不表示恢复 Windows 支持。

Consequences

  • 正面：本地启动链路统一为 POSIX Shell；文档和实现的支持范围一致；平台错误在入口处明确暴露。
  • 负面：Windows 启动、安装、Maven 包装和 Task Scheduler 集成立即停止；旧用户需要自行维护分支或迁移到受支持平台。
  • 兼容性：CLI 参数、JAR、HTTP API、配置文件与持久化格式均未变化；变化仅涉及受支持平台及其入口文件。
  • 回滚：若未来恢复 Windows 支持，需要新 ADR，并重新建立脚本、调度器、CI、文档和平台验证，不能只恢复单个 Batch 文件。
  • 数据：无数据库或本地数据迁移；本次变更不自动删除旧 Windows 环境中已创建的 PATH 条目或系统任务。
