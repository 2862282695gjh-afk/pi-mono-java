Context

变更前的实现使用应用内 SVG 近似品牌图，外层是近黑圆角方块；这与用户确认的 O1 透明位图在形状、间距和展示方式上不同。界面同时把 Runtime 原始 thinking 文本放入可展开区，并用带边框的大卡片显示工具结果，既偏离 v8 视觉稿，也把私有推理误当成可直接展示的产品内容。

当前 Runtime HTTP 1.38.0 会发送 assistant.thinking.* 原始内容，却还没有公共 bridge 生成的安全 thinking 摘要字段。Assistant completed 内容包含工具名和参数，工具生命周期事件包含执行状态与结果。浏览器过渡 adapter 因此可以实现安全降级和纵深脱敏，但不能替代目标生产 bridge 的网络边界。

Decision drivers

  • 实现中的品牌标识必须与用户确认的 O1 像素级同源，不允许重新生成、描摹或套入额外底板。
  • Agent 活动应像 Codex 风格工作台一样紧凑、连续、可展开，但不能把原始推理暴露给用户。
  • 工具详情必须按输入在上、输出在下阅读，并限制敏感字段、内部 ID、绝对路径和超长内容。
  • 当前 Runtime 契约缺字段时应安全降级，不得用原始内容补齐产品摘要。

Decision

  • BrandMark.vue直接引用权威 campusclaw-mark-o1.png。实现资产与设计资产 SHA-256 均为 68150b9c669a7d3f5b4b306aeb79092852b308a127ec9cc522b48be6a47551cc，不添加深色方块、裁剪或重绘。
  • 浅色 Token 使用主表面 #FFFCFA、侧栏 #F8F3F0、辅助表面 #F4ECE8、选中态 #EFE4DE、主文本 #2C2724、主动作 #2B2522。O1 珊瑚色 #D97757只承担品牌识别；运行和完成继续使用绿色。
  • Thinking 投影只读取 thinkingDisplayTitle/thinkingDisplaySummary，兼容未来 bridge 的 displayTitle/displaySummary。原始 delta、content 和其他 thinking 文本永不进入产品 turn；无安全摘要时只显示“正在分析”或“分析过程”状态。
  • Thinking 与 Tool 分别使用专用 disclosure。当前项默认展开，已完成工具默认折叠；工具尚未开始执行时不创建可见活动。详情固定按“输入参数 → 输出结果”纵向排列。
  • 工具参数在投影层扁平化，最多 12 行、3 层和每值 240 字符。凭据、Cookie、Token、内部 Agent/Session/Tool/File ID 及类似 Bearer/JWT 值显示为“已隐藏”；绝对路径只显示最后一段。工具结果最多 4,000 字符并以纯文本显示。
  • 同一用户消息后的连续 Assistant 活动只在第一项显示一次 O1；后续 Thinking、Tool 与 Assistant 内容保持同一视觉列，避免重复品牌噪声。

Intentional differences

产品约束：高保真稿中的附件名称、行数和工具输出是说明性样例；实现只展示 Runtime 实际返回且通过投影策略的数据。

安全加固：当前 Runtime 只提供原始 thinking 时，实现故意比视觉稿信息更少，显示状态而非推理。工具参数的浏览器脱敏是过渡纵深防护，生产目标仍要求公共 bridge 在内容到达浏览器前完成最小化和脱敏。

架构变化：Thinking 和 Tool 从 Assistant Markdown 中分离为独立产品对象和专用 viewer；Assistant Markdown 的安全边界继续由 ADR-0027 约束。

Consequences

正面：实际界面与 O1 v8 设计同源；Agent 活动更紧凑；原始推理、凭据和内部标识不会因富文本能力而进入 DOM；移动端仍保留纵向扫描与局部表格滚动。

负面：在公共 bridge 尚未提供安全摘要前，Thinking 只有状态信息；客户端脱敏规则需要与未来服务端字段策略保持一致；471 KB 的原始 O1 PNG 会直接进入构建产物。

Validation

  • runtimeEventProjector.test.ts验证原始 thinking 不投影、安全摘要投影、工具延迟出现、参数隐藏和绝对路径收敛。
  • 桌面 1280×720 与移动 390×844 浏览器验收覆盖 O1 比例、暖色 Token、disclosure 展开、纵向工具详情和表格局部滚动。
  • 前端必须通过 npm test、npm run typecheck、npm run build 和 npm audit --audit-level=high。
