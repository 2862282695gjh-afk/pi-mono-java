ADR-0055：Runtime 持久化不依赖请求流

后续约束以设计 main 0a113ce8e12cc65bd6e5589087bd4642a7d016e1 相同 README 第 7 节为准： Compact 不支持 Steer/FollowUp，不排队续跑，Mate Header 只保留至本次压缩结束。设计仓只读，未修改。

Context

Compact 要返回普通 JSON，且在没有请求 SSE 时保存权威领域历史。原 ActiveExecution、Projector 和执行收尾 直接依赖 RuntimeEventStream；执行上下文还要求一条初始用户消息。创建一个永远没有订阅者的流会引入无用缓冲。

Java 证据路径前缀为 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/： runtime/RuntimeActiveExecution.java:eventStream、event/RuntimeEventProjector.java:emitPersisted、 event/RuntimeExecutionCoordinator.java:completeExecution。这些是变更前行为，不是 Compact 已实现的证据。

选项与取舍

  • 无人订阅的 SSE：改动少，但仍缓存、构造响应事件和申请请求资源，不采用。
  • 到处检查 null stream：简单但把传输条件散布到持久化和收尾，不采用。
  • 复制第二套 Projector：局部独立但会分裂压缩边界、Usage 和恢复语义，不采用。
  • 明确可选输出策略：增加一个接口与无状态实现，保留同一持久化路径，采用。

Decision 与理由

  • RuntimeEventOutput 同步求值或丢弃事件工厂，不保留闭包。原 RuntimeEventStream 适配旧队列； persistenceOnly 不创建 SSE VO、不编码、不翻译终态文案、不申请缓冲。
  • Projector 先执行原 Repository 事务，再记录成功返回的 Compaction Entry 序号，最后调用可选输出。 不用 Usage 或后续排队消息的序号替换压缩结果。
  • createForCompaction 不伪造初始用户消息，不承担准入/启动。POST Events 使用独立纯载体 RuntimeExecutionContextDTO， 保存自己的流引用；Controller 不接触内部 DTO。
  • 输出完成与执行完成分离；无流策略没有请求状态，不获得取消权。6a 没有改变既有 POST Events 的超时和控制行为； 这些旧路径不构成 Compact 继续消费队列或复用旧 Abort 响应的授权。

pi 4af9d21d3b4d664e4a29fcabfec85171077248e3 的 packages/coding-agent/src/core/agent-session.ts:compact 先 abort、写 Compaction、重建消息后通知终态； abortCompaction 取消压缩信号。Java 的 idle-only 与 JSON 是产品约束，可选输出和数据库序号是架构差异， 不能称为 pi 已有 HTTP 行为。

Consequences

  • 正面：不复制领域投影；无请求流仍可保存和恢复压缩，旧 SSE 路径继续使用原有缓冲。
  • 代价：输出接口要求同步求值；未来实现不得异步保留捕获 Projector 状态的工厂。
  • 限制：lastCompactionEntrySeq 是最近成功值，后续失败不清除。Compact 协调器必须检查本次失败并固定本次结果， 关闭控制接收，不消费任何控制队列。
  • 后续：6b 按已准入执行、原子准入/空历史两个职责串行交付，覆盖容量/30 分钟超时/独立完成句柄与失败清理； 压缩终态释放 Holder 与本次 Mate 凭据，之后接入 Handler 和共享 Builtin/Skill HTTP。
  • 范围：通用 Events V2、旧控制路由退役及前端迁移由用户另行开发，不是当前 Slash 工作的交付前置条件。 命令专属中断绑定/响应仍需独立确认，不恢复旧 Abort 204。
