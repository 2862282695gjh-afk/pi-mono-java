ADR-0015 · 移除本地沙箱并统一由工具管理器管理受管控工具

Status: Superseded · Date: 2026-08-19 · Amended: 2026-08-28 · Tool assembly replaced by: ADR-0022 · Deployment assets replaced by: ADR-0033 · 设计文档: sandbox-cleanup · 基线: origin/main@7811dc335fcb0125a1ecbddd63cd77baf120f21d

Context

基线同时包含普通本地工具、Docker Sandbox、Hybrid Tool、本地执行路由和 Skill Sandbox Parser。Kubernetes 部署还依赖 Docker sidecar、Docker socket、特权容器及 Docker readiness。该组合使工具所有权、配置、Schema 与运行时隔离语义分散在 CampusClaw 和部署脚本两侧；基线已经提供 ToolCatalog、MateToolClient、ListMateTool 与 CallMateTool，因此继续维护本地 Docker 路由会形成两套工具管理权威。

Options considered

  • 继续保留本地 Docker Sandbox 与 Hybrid 路由
    Pro：保留既有本地隔离路径，迁移风险小。
    Con：继续承担 DinD、Docker socket、特权权限和双套配置；工具 Schema 与远程管理器的所有权仍然分裂。Rejected。
  • 保留沙箱代码但默认关闭
    Pro：可以通过配置快速恢复旧实验能力。
    Con：死代码仍会被测试、镜像、脚本和文档重新引用；配置兼容层延长迁移边界，无法保证单容器部署。Rejected。
  • 删除本地沙箱和 Hybrid，保留本地基础工具并把受管控工具交给 MateService
    Pro：本地路径、超时和输出截断语义保持稳定；工具元数据、授权和远程执行集中管理；Kubernetes 可以退化为单容器。
    Con：本地 JVM 不再提供 Docker 容器隔离，旧沙箱配置和脚本不再兼容；运维必须单独清理历史 Docker 资源。Chosen。

选择理由：目标是收敛工具管理边界，而不是继续扩展本地隔离产品。删除属于架构迁移；本地安全能力仅保持既有路径校验、超时和输出截断，不构成新的沙箱保证。

Decision

  • 删除 tool/sandbox、tool/hybrid、ExecutionRouter、ToolExecutionStrategy、SandboxSkillParser、沙箱配置模型及实验脚本/镜像/Compose 文件。
  • 保留 BashTool、ReadTool、WriteTool、EditTool、GlobTool、GrepTool，以及 ToolCatalog、MateToolClient、ListMateTool、CallMateTool。
  • 保留 Agent Core 的 ToolExecutionMode，它只表示一次模型响应中的工具调用串行/并行调度，不表示沙箱或工具归属。
  • 删除 tool.execution.*、TOOL_EXECUTION_*、DOCKER_HOST 与 SKILL_SANDBOX_PARSING 的运行时支持；不提供兼容别名。
  • 将根 Dockerfile 和 Kubernetes 工作负载收敛为单应用容器；保留工作区/PVC、Service、HPA、PDB 和健康检查，删除 DinD sidecar、Docker socket、特权权限和 Docker readiness。
  • 外部旧容器和 volume 只在发布运维确认后执行清理，本 ADR 不授权代码自动执行破坏性删除。

后续取代：本 ADR 保留单容器 Docker/Kubernetes 清单的部署决定已由 ADR-0033 取代。当前仓库不维护 Dockerfile 或 Kubernetes 部署资产；未来 Kubernetes 框架需要独立设计。

Consequences

  • 正面：工具管理边界清晰；构建镜像不再依赖 Docker CLI/daemon；Skill 加载链路更短；单容器部署不再需要 DinD 权限。
  • 负面：旧沙箱配置、脚本和实验文档失效；本地工具不具备 Docker 容器隔离；需要通过 MateService 提供受管控的远程工具执行。
  • 回滚：只能回滚到一个完整的旧版本，同时恢复源代码、配置、镜像、Docker daemon、sidecar、卷和权限；不支持只恢复单个沙箱类。
  • 数据：无数据库表、字段或迁移变化；历史 Docker 容器和 volume 不由应用启动或升级流程自动删除。
