Context

分析基线中，AgentRuntimeManager#requireAgentRoot 先要求 agentId 符合 agent- 加 32 位十六进制字符的领域格式，再调用 toAbsolutePath().normalize().resolve(agentId).normalize() 生成缓存目录。该格式不接受路径分隔符、.. 或绝对路径，因此普通请求不能直接提交词法目录逃逸载荷。

toAbsolutePath() 与 normalize() 不会解析文件系统中的符号链接。路径拼接完成后也没有独立验证最终目录仍位于 Agent 根目录下，因此已有 Agent 目录若是指向外部目录的符号链接，缓存读取可能沿链接访问根目录之外。安全边界同时隐式依赖 ID 正则，静态分析无法从路径操作本身确认包含关系。

审查实现提交 90e78251885814a34b8e054ea7f44f86baecbb1b 已使用 canonical path 和 Path#startsWith 阻止根目录外目标，但仍接受根目录内别名。若 agent-A 是指向 agent-B 或 agentsRoot 的符号链接，canonical 候选仍以 canonical 根目录开头；返回 canonical 目标后，后续符号链接检查已失去原始目录身份。refresh(agent-A) 可能因此修改 agent-B 的缓存，并绕开按 agent-B 建立的锁。这是观察到的审查实现行为，不是目标设计。

Decision drivers

  • 遵守公司文件路径规范，使用 canonical path 而不是 absolute path 作为安全判断依据。
  • 让每个动态路径拼接点自身具备可审计的根目录包含性保证。
  • 保持请求 agentId 与受管目录的一一对应，禁止根目录内符号链接别名。
  • 保留现有领域 ID 校验，不降低对非法输入的拒绝强度。
  • 在任何文件读取、目录创建或远端访问前失败。
  • 不改变合法 Agent 的磁盘布局与缓存、refresh 或发布行为。

Considered options

只依赖 Agent ID 正则和 absolute path

优点：不增加代码。
缺点：路径安全与领域格式规则耦合，absolute path 不解析符号链接，拼接结果没有独立、显式且 fail-closed 的验证。拒绝。

使用 Path#toRealPath

优点：返回真实文件系统路径并解析符号链接。
缺点：冷启动时目标 Agent 目录尚不存在，toRealPath 会失败，无法支持现有按需创建流程。拒绝。

使用 File#getCanonicalPath 后只执行 Path 包含性校验

优点：支持尚不存在的目标目录，解析已有符号链接，并阻止根目录外目标。
缺点：无法区分请求目录与根目录内的 canonical 目标，会接受指向其他 Agent 或根目录的符号链接别名。拒绝。

使用 canonical path，并校验包含关系与目录身份

优点：保留冷目录按需创建能力，同时拒绝根目录外目标和根目录内别名；路径安全与逻辑资源身份均可独立审计。
缺点：canonical path 解析可能产生 I/O 错误，需要明确失败语义。接受。

Decision

  • 使用 File#getCanonicalPath() 获取配置 agentsRoot 的 canonical path，不使用 toAbsolutePath() 作为安全边界。
  • 用 canonical 根目录和已验证的 agentId 构造预期 Agent 子目录，并再次调用 getCanonicalPath()。
  • 要求 canonical 候选路径 startsWith canonical 根目录，并与预期 Agent 子目录精确相等；任一条件失败时抛出 IllegalArgumentException。
  • canonical path 解析失败时抛出 AgentRuntimeException，不继续文件或远端操作。
  • 保留 AGENT_ID_PATTERN 前置校验，使非法领域 ID 在路径操作前被拒绝。
  • 增加真实符号链接回归测试，覆盖指向根目录之外、根目录内另一 Agent 和根目录本身的三种目标。

Intentional difference

安全加固：合法 Agent 的行为与目录布局不变；新增行为会拒绝 canonical path 不属于配置根目录的路径，以及指向根目录内其他资源的符号链接别名。该校验不是对 pi 既有行为的描述，而是 CampusClaw Java 实现新增的路径边界与资源身份保证。

Consequences

  • 正面：动态路径拼接点可以基于 canonical path 独立证明不会逃逸 agentsRoot。
  • 正面：已有 Agent 路径中的符号链接不能把缓存读取引导到配置根目录之外。
  • 正面：一个 Agent 的符号链接不能把 refresh 或发布重定向到另一个 Agent 的缓存。
  • 正面：将来即使 ID 规则被放宽，路径包含性仍有独立保护。
  • 兼容性：所有当前合法 agentId 继续解析为原目录。
  • 失败语义：包含性验证失败时，在文件系统或 Mate 产生副作用前抛出参数异常。

Validation

  • 执行 AgentRuntimeManagerTest，覆盖非法 ID、canonical 结果逃逸、跨 Agent 别名和根目录别名拒绝路径。
  • 执行格式、Checkstyle、模块测试、镜像同步与 Git diff 检查。
  • 验证设计文档不含 Mermaid、PlantUML 为 ASCII、SVG 与源码链接有效。
