ADR-0083：区分固定结果段与根执行终态读取

Status: Accepted · Date: 2026-09-08 · Version: 1.0.0

Context

设计仓2ee2a321要求控制请求绑定原执行，每条确认响应只读自己的结果段。 Java基线201d75ed已有根执行、段和公共事件关联，但没有结果补读接口。pi4af9d21d通过本地事件和AbortSignal运行， 没有CampusClaw共享数据库和HTTP段。新增固定结果读取属于本项目架构变化。

Decision

提供readSegmentEvents和findExecutionTerminal两个只读接口，都验证Session、execution、root和segment。 段事件按序读取并以该段terminal_event_seq为上界；根执行读取只返回TERMINAL记录指向的真实idle。

选项与理由

按Session当前状态读取会误选下一轮；返回全部段关联可能包含首个confirming之后的terminated。 两个接口明确区分终点，既支持确认响应在首个idle结束，也支持中断响应等待同一执行的真实结束。

Consequences

身份不匹配时返回空，不跟随当前执行。只读查询复用现有索引，无新增依赖、线程或凭据持久化。 调用方必须维护内部游标并负责响应容量、查询超时与失败退避；本片不切换HTTP，也不管理原执行Holder。

验证

数据库回归验证固定身份、分页和同段两个idle的不同终点；实际运行结果及生成镜像限制记录在关联设计。
