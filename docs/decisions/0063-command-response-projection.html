ADR-0063：命令业务响应与发现白名单投影

Status：Accepted · Date：2026-09-07 · Version：1.0.0

Context

基线 pi-mono-java@ca2600da15dfaf8dda1f16b9d2f3d130b5d9ace5 已提供完整权威 Session 内部结果和 Session/Models 业务 VO。内部 Command DTO 仍包含准入原因、输入候选和私有快照， 不能直接用于公共 JSON。设计只读依据为 pi-mono-java-design@88f4df16bc24bbfcd28e1ec374feb2de0db8be3b， Builtin 2.9.0 §8/8.1、Slash 1.6.0 §3.1、Help 1.2.0。

源码根 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/： dto/command/SessionCommandResultDTO.java、session/RuntimeSessionResponseAssembler.java:getView、 vo/AvailableModelsResponseVO.java、command/catalog/ResolvedCommandCatalog.java:list、 service/command/SkillCommandSource.java:list。本次以 Java API 为基线，不宣称 pi 已有 HTTP 投影。

考虑过的选项与取舍

  • 直接序列化 DTO：代码少，但泄漏内部回执、快照和数据层类型，拒绝。
  • 为每个命令复制一份响应：调用局部化，但 Session 字段及 ETag 规则会漂移，拒绝。
  • 一次实现完整 GET/POST：整体连通，但突破本次独立职责与 PR 预算，留到依赖完整后。
  • 先交付类型化业务投影和 Catalog 纯投影：可独立验证，不改变执行与路由，采用。

Decision 与理由

  • CommandResponseAssembler 委派 Session 组装器，模型直接复用 AvailableModelsResponseVO。 Help/Compaction/Skills 仅增加三个最小业务 VO，不回显 command/changed/sourceEventSeq。
  • Session 正文和 ETag 取自同一个结果 DTO；不提交后 GET，不使用旧 Catalog 拼字段。
  • 发现只消费一个已解析 Catalog 的 availability；固定 Builtin 顺序后追加 Skill 字典序。 name/kind/description/可选 input 为白名单；hint 固定，附件只在 Skill true 时输出。
  • 新 VO 使用只读 final 字段与防御复制，嵌套 Skill 和描述符均为 VO。 字段级省略不影响 Session 的 null 显示名或其他成功数组。
  • 这属于已确认的产品字段约束、Java 架构复用与安全边界落实，不是新的产品契约。

Consequences

  • 正面：响应资源只有一份定义，内部元数据不能随着 DTO 扩展意外进入 JSON。
  • 代价：类型化叶子投影与统一执行分派分步交付；本片未注册 HTTP，也不执行 Compact。
  • 后续：共享发现应用必须读取单个完整 Agent 缓存，无缓存整体 503 和 Retry-After: 3。 当前空 Catalog 投影成功不代表缓存缺失可返回空清单；POST Help 的既有 422 不变。
  • 后续：统一结果类型分派、Compact DTO 接入和共享 HTTP 在依赖合入后完成，不堆叠未合入分支。
  • 无新 Maven 依赖、数据库或升级脚本；设计仓保持只读，Skill 执行待决内容未被代决。

验证与范围

精确 JSON、Session/ETag 同源、非零 Usage、列表不可变、发现顺序和字段省略由新测试覆盖。 交付验证记录在实现说明及 PR；纯投影测试不等于完整 HTTP 或跨进程执行验收。 公司 NativeParent 未解析时明确保留镜像编译未验证限制。
