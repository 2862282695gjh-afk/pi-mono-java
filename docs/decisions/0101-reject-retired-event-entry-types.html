ADR-0101：拒绝退休事件类型进入权威历史

Status: Accepted · Date: 2026-09-08 · Version: 1.0.0

Context

Events v2 设计基线 pi-mono-java-design@2ee2a321 只把完整事件写入权威历史， preview delta 不持久化，流结束也不形成公共历史事件。Java 基线 69b8ced3 中，旧 RuntimeEventProjector 和 RuntimeTerminalEventFactory 仍把八个旧名称用于瞬时 SSE， 但生产代码没有把这些类型写为 RuntimeEntryDTO。最终 HTTP 分支通过 8ea0ba9f 删除旧控制与终态链、465dd631 删除 Entry 历史投影、 c2fed32e 删除普通 Agent 投影分支，随后在 e866db6b 删除对应枚举。

RuntimeSessionMapper.xml#countUnmappedCurrentBranchEntries 仍把这些类型登记为允许且必须 投影零条公共事件。手工或缺陷写入的退休 Entry 只要附加 event_count=0，GET 就会把它当成 完整记录并静默跳过，削弱首版运行时的关闭失败边界。

Decision

从权威历史的已登记 Entry 类型和零事件类型集合中同时删除以下八种类型： assistant.message.started、assistant.message.delta、 assistant.thinking.started、assistant.thinking.delta、 tool.execution.delta、tool.execution.completed、 stream.end、stream.error。

GET 在当前分支遇到其中任何一种类型时按未知或退休类型处理，即使存在精确的零事件 marker 也返回 EVENT_LIST_FAILED。保留当前运行时明确使用的完整事件类型，以及允许零事件的 assistant.thinking.completed、内部 Compact 状态和结构辅助记录。当前产品是第一版，不为退休类型 增加迁移、兼容读取或恢复入口。

考虑过的选项及取舍

  • 保留零事件兼容白名单。 可以继续跳过旧类型，但首版没有需要兼容的已发布历史，并会让无合法写入者的数据被误判为完整，因此不采用。
  • 只删除 Java 枚举。 能收敛编译期类型，却不能阻止数据库中的手工或缺陷记录绕过完整性门禁，因此不采用。
  • Java 与 SQL 按各自职责收紧。 最终 HTTP 集成删除旧瞬时编码器，本决策让权威历史立即拒绝退休 Entry，采用此方案。

Consequences

当前版本不会为 preview、工具过程增量或流结束生成历史 Entry。若数据库出现退休类型，GET 明确失败， 便于发现事务外写入、程序缺陷或数据损坏，不会返回看似成功但缺项的历史。Compact 私有记录和结构辅助记录 仍可用显式零事件 marker 参与当前分支完整性检查。

本决策不修改前端或 agent-core，不增加 Maven 依赖，也不改变 Events v2 的公共响应类型。

Validation

提交 ab0f2637 增加真实 openGauss 参数化回归，逐一手工插入八种退休 Entry 和 event_count=0 marker，16 项查询测试全部通过；同一组测试保留当前分支、数字分页、Thinking 可见性、工具调用和 Compact 零投影行为。
