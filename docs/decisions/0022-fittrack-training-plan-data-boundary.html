ADR-0022 · FitTrack 系统动作与用户计划的 RLS 边界

Status: Accepted · Date: 2026-08-24 · 设计文档: fittrack-training-plans

Context

动作库既需要约 50 个所有用户共享的预置动作，也需要用户创建私有动作；训练计划必须能原子地保存有序动作，且不得信任客户端传入的 owner。

Decision

采用单个 exercises 表：系统行的 owner_id 为 null，用户行的 owner_id 为 auth.uid()。RLS 允许已认证用户读取系统行或自己的行，仅允许用户创建、修改、删除自己的自定义行。计划和计划动作均由 owner RLS 隔离；save_workout_plan 在数据库端验证归属与排序并原子替换动作。

考虑过的选项

选项ProCon
分离系统/用户动作表语义直观查询和计划外键需要 union 或双外键
单表 + nullable owner（选定）统一查询、单一计划外键、RLS 明确策略需区分系统和私有行
客户端删后逐条保存计划动作实现简单断网/并发时会留下半成品计划

Consequences

  • 正面：预置动作和用户动作以一次查询提供；用户无法篡改系统数据或他人计划。
  • 负面：RPC 是计划编辑的受控写入口；后续迁移需维持其输入契约。
