Context

PR #210 已提供 Skill 发现 DTO 和 Catalog，但缺少来源前置过滤及可执行定义。 七个 Builtin 需要独立 Handler 和准入，Help 与执行应使用同一快照。 Skill Command 由其他同事并行实现，不得把本会话范围误写为产品禁用或延期。

历史核心实现源码位于 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/command/： 基线的 CompositeCommandRegistry.resolve 聚合全部 Source； 本 PR 的 BuiltinCommandSource、BuiltinCommandDefinition.describe 建立分层核心。 pi 4af9d21d3b4d664e4a29fcabfec85171077248e3 的 packages/coding-agent/src/core/agent-session.ts:_tryExecuteExtensionCommand 提供 Handler 与上下文的行为参考，不是企业 HTTP 契约。

分包实现中，源码根目录保持为 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/； CompositeCommandRegistry.resolve 与两个来源服务位于 service/command/， 内部 DTO 位于 dto/command/，核心分别位于 command/{definition,builtin,execution,catalog,source,type}/。 完整类型归属见关联设计文档；旧路径只作为对应提交的历史证据。

考虑过的选项及取舍

  • 中央名称 switch：起步代码少，但每个新命令必须修改同一分派器，拒绝。
  • 所有定义强制 Handler：调用面统一，但展示 Skill 只能安装抛错占位，拒绝。
  • 按来源过滤并区分展示/可执行定义：类型稍多，但保留独立扩展、同一请求身份与无环 Help，选择。

Decision

  • Source 显式声明 kind，Registry 在解析前选择来源；保留全来源 resolve。
  • Builtin Contributor 在启动时贡献固定定义；BuiltinCommandSource 拒绝重名。
  • 定义接口只含 describe；Builtin 组合元数据、准入和 Handler；展示定义不带假 Handler。
  • 一次 Catalog 同时固定描述符、定义索引和 Session 观察 DTO；Context 复用 Catalog。
  • DTO、Spring 服务与核心职责按包分层。通用定义不依赖 Builtin 定义， 依赖保持为 builtin → execution → catalog → definition → dto → type；来源 SPI 不依赖实现服务。
  • 准入预览不代替锁内复核；内部结果使用 DTO，未来应用层转独立只读 VO。
  • 本 PR 不发布路由、不持久化通用命令历史、不实现七个具体命令或 Skill 执行。

所选方案与理由

此决策属于 Java 内部架构变化。源过滤避免 Builtin 依赖 Skill 文件读取； 保留全来源入口与开放定义接口，让同事可独立实现 Skill 执行。 Builtin JSON 目标已确认，但不据此决定 Skill 的最终公共请求形状。

Consequences

  • 正面：启动即发现重名；列表、Help、分派不再重复解析。
  • 正面：无请求可变字段、无凭据保存、无新增线程或数据库。
  • 代价：自定义 Source 必须补 kind；准入策略及 Handler 的无请求状态仍需代码评审保证。
  • 迁移：更新 import，不保留旧包占位；Catalog 构造器开放给跨包注册服务， 其排序、查重和快照行为不变。不新增 Controller、VO，不进行全仓 MVC 重构。
  • 后续：各窄服务必须锁内复核；Compact 独立实现不传播客户端取消的完成句柄。
  • 后续：最终 HTTP 发布前与 Skill 开发线对齐，不用 Builtin-only 正则禁止 skill:*。
