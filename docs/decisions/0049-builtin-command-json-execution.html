Context

PR #210 已提供 Skill 发现 DTO 和 Catalog，但缺少来源前置过滤及可执行定义。 七个 Builtin 需要独立 Handler 和准入；列表、准入和分派使用同一 Catalog 快照。 当前由用户统一负责 Builtin 与 Skill 的设计、实现和集成；独立扩展点不等于不同负责人， Skill 执行和共享 HTTP 对齐纳入统一验收，不得把 Name 切片范围误写为整体范围。

历史核心实现源码位于 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/command/： 基线的 CompositeCommandRegistry.resolve 聚合全部 Source； 本 PR 的 BuiltinCommandSource、BuiltinCommandDefinition.describe 建立分层核心。 pi 4af9d21d3b4d664e4a29fcabfec85171077248e3 的 packages/coding-agent/src/core/agent-session.ts:_tryExecuteExtensionCommand 提供 Handler 与上下文的行为参考，不是企业 HTTP 契约。

分包实现中，源码根目录保持为 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/； CompositeCommandRegistry.resolve 与两个来源服务位于 service/command/， 内部 DTO 位于 dto/command/，核心分别位于 command/{definition,builtin,execution,catalog,source,type}/。 完整类型归属见关联设计文档；旧路径只作为对应提交的历史证据。

考虑过的选项及取舍

  • 中央名称 switch：起步代码少，但每个新命令必须修改同一分派器，拒绝。
  • 所有定义强制 Handler：调用面统一，但展示 Skill 只能安装抛错占位，拒绝。
  • 按来源过滤并区分展示/可执行定义：类型稍多，但保留独立扩展、同一请求身份与无环 Help，选择。

Decision

  • Source 显式声明 kind，Registry 在解析前选择来源；保留全来源 resolve。
  • Builtin Contributor 在启动时贡献固定定义；BuiltinCommandSource 拒绝重名。
  • 定义接口只含 describe；Builtin 组合元数据、准入和 Handler；展示定义不带假 Handler。
  • 一次 Catalog 同时固定描述符、定义索引和 Session 观察 DTO；Context 复用 Catalog。
  • DTO、Spring 服务与核心职责按包分层。通用定义不依赖 Builtin 定义， 依赖保持为 builtin → execution → catalog → definition → dto → type；来源 SPI 不依赖实现服务。
  • 准入预览不代替锁内复核；内部结果使用 DTO，未来应用层转独立只读 VO。
  • 核心切片（PR #218）不发布路由、不持久化通用命令历史、不实现七个具体命令或 Skill 执行。

所选方案与理由

此决策属于 Java 内部架构变化。源过滤避免 Builtin 依赖 Skill 文件读取； 保留全来源入口与开放定义接口，使 Builtin/Skill 的实现边界独立，并由用户统一集成。 Builtin JSON 目标已确认，但不据此决定 Skill 的最终公共请求形状。

Consequences

  • 正面：启动即发现重名；列表、准入和分派不再重复解析。
  • 正面：无请求可变字段、无凭据保存、无新增线程或数据库。
  • 代价：自定义 Source 必须补 kind；准入策略及 Handler 的无请求状态仍需代码评审保证。
  • 迁移：更新 import，不保留旧包占位；Catalog 构造器开放给跨包注册服务， 其排序、查重和快照行为不变。不新增 Controller、VO，不进行全仓 MVC 重构。
  • 后续：各窄服务必须锁内复核；Compact 独立实现不传播客户端取消的完成句柄。
  • 后续：由用户在最终 HTTP 发布前统一对齐 Skill 清单与请求类型，不用 Builtin-only 正则禁止 skill:*。

只读实现切片（1.3.0）

从 origin/main@6d7ba8483f69e8cccab04489a0111a27fde1315d 串行创建下一分支； 初始实现提交为 21d19792ce72546a7d0072501463dd4c1241b669， 新版 Help 实现为 2ceb3f7319e61c6d036526f4ccd2f6e56114ac5a。 本切片沿用已确认的分层决策，不修改 pi-mono-java-design，不发布 Command HTTP 路由。

  • service.command.contributor 中三个 Contributor 各自提供元数据、准入和真实 Handler lambda， 依赖 service.command.readonly 中对应窄服务；不增加中央名称 switch 或其他命令的占位实现。
  • AgentHelpQueryService.query 按 Session Agent ID 读取一次完整本地缓存，返回显示名、 用途介绍和使用场景；RuntimeSessionStatusService.query 只读持久化 Session 观察值， BoundSkillQueryService.query 同样调用 AgentRuntimeManager.prepareCached。 三个查询在 idle/running 均允许；Help / Skills 无完整快照时失败，不主动刷新。
  • Help 改为 NONE；纯空白参数视为空，其他参数返回 INVALID_COMMAND_REQUEST。 命令目录由后续 GET Commands 接口负责，不再由 Help 复用 Catalog 展示。
  • AgentRuntimeManager 在既有 schemaVersion 下保存并恢复 userCases； 旧缓存缺字段恢复为空列表，非法文本项使快照不可用。prepareCached 与刷新发布共用 Agent 锁，显式刷新失败继续保留上一完整快照。
  • 没有在 DTO 构造器中实施参数或业务校验；三个结果 record 位于 dto.command。 DTO 列表只作防御复制；参数语义由窄服务校验，统一 HTTP 请求校验和 DTO→VO 留给后续切片。
  • Help 不依赖 Registry，避免反向注入环；Status 观察持久化状态；Help / Skills 的本地完整 快照查询没有远端调用和运行状态变更，且不会跨原子发布混合两代缓存文件。
  • 代价：此时仅三个真实命令可供内部集成；Skills 仍承担既有完整目录读取成本。 后续应用层必须完成授权，并同时捕获 Handler 的同步抛错及 Stage 的异步失败。
