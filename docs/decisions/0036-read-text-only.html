ADR-0036：Read 仅支持 UTF-8 文本读取

Context

收敛前的 Read 同时承担文本分块和本地图片输入：它按扩展名和 MIME 识别 JPEG、PNG、GIF、WebP 与 BMP，解码后将长边缩放到 2,000 像素以内，再向模型返回 Base64 ImageContent。该路径还使工具工厂必须读取模型图片模态，并引入专用 imageio-webp 运行时依赖。

产品现在只希望通过 Read 向模型暴露可分块、可截断的工作区文本，不希望 本地图片因文件后缀自动进入模型上下文。

Decision drivers

  • 让 Read 的公开描述、运行时输出类型和实际能力都固定为 UTF-8 文本。
  • 消除本地图片解码、缩放和 Base64 复制带来的内存和依赖成本。
  • 保留现有 Agent 工作区、符号链接拒绝、文本分块、截断和取消语义。

Considered options

保留现有文本和图片双能力

优点：模型可直接观察工作区图片。
缺点：与新的纯文本产品边界冲突，继续保留图片处理和 WebP 依赖。拒绝。

图片只返回路径或提示文本

优点：模型仍能知道目标是图片。
缺点：仍需要按 MIME 或扩展名建立图片特殊分支，并且与普通二进制错误产生两套语义。拒绝。

只支持严格 UTF-8 文本

优点：单一输出类型、单一错误边界，可删除图片专用代码和依赖。
缺点：依赖 Read 观察本地图片的 Agent 需要调整。接受。

Decision

  • Read 的描述固定为读取 UTF-8 文本文件，成功结果只包含 TextContent。
  • 保留 1-based offset、limit、默认 2,000 行和 50 KiB 输出上限。
  • 含 NUL 或无法严格按 UTF-8 解码的文件统一以 Unsupported binary file 失败。
  • 删除 MIME 检测、图片解码/缩放/Base64 分支、模型图片模态判断、ImageUtils 及 imageio-webp 依赖。
  • 通用 AI 模型层的 ImageContent、InputModality.IMAGE 和 Provider 图片能力不属于本次删除范围。

Intentional difference

产品约束：不再通过 Read 把本地图片送入模型。架构变化：工具从基于 MIME 的文本/图片双分支收敛为严格 UTF-8 文本路径。工作区安全边界不变。

Consequences

  • 正面：工具不再产生 ImageContent，也不会根据当前模型模态改变输出。
  • 正面：删除 WebP SPI 依赖及图片解码、缩放和 Base64 的额外内存复制。
  • 负面：JPEG、PNG、GIF、WebP 和 BMP 等二进制图片现在以不支持的二进制文件失败。
  • 边界：可解码为 UTF-8 的文本文件仍按文本读取；工具不以文件后缀拒绝文本。
  • 边界：文本路径仍使用 Files.readAllBytes 后解码，流式读取不属于本决策。

Validation

  • ReadToolTest 验证公开描述、文本分块、截断、二进制拒绝和 PNG 文件头拒绝。
  • 定向 Maven 测试覆盖 ReadTool、操作接口、工具装配和工作区边界。
  • 主模块和 mate-campusclaw 镜像必须编译通过，依赖树不得再包含 imageio-webp。
