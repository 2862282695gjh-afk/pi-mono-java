Accepted ADR-0026 · 2026-08-26

统一 CampusMate 客户端的服务身份、地址与 Endpoint 目录

决策范围：CampusClaw 的 Model、受管 Runtime、Tool 客户端配置和安装变量映射。

上下文

实施前源码基线 56be8eee59415a5f86658d6635a7b7e8891263d3 把同一个 CampusMate 服务拆成 campusmate.model-manager、campusmate.runtime 和顶层 mate 三个配置入口，分别声明服务地址，并用七个 path 键描述六个 HTTP operation。Runtime 与 Tool 的 Skill query 是同一 method + path，却分别配置。

这种结构允许三个客户端被误配到不同 origin，也让 mate.innerGWSerive 的历史拼写 继续进入应用契约。用户已明确 mate 与 CampusMate 是同一服务，并选择将 model-manager 配置分组缩写为 model。

决策

  • 只保留一个必填 campusmate.base-url，供 Model、Runtime 和 Tool 客户端共享。
  • 在 campusmate.endpoints 中按 HTTP operation 维护六个 service-local path；Runtime 与 Tool 复用一个 Skill query 条目。
  • 模型本地参数放入 campusmate.model，Runtime 本地参数放入 campusmate.runtime，Tool 开关放入 campusmate.tool。
  • 删除顶层 mate.*、campusmate.model-manager.* 和各客户端独立 base URL；应用不双读旧键。
  • 安装脚本可在边界把部署平台旧变量 CAMPUSINNERGWSERVICE_DOMAIN_NAME_URL 转换为 CAMPUSMATE_BASE_URL；显式新旧值冲突时失败。
  • 新增类型化配置校验：origin 只能是无服务路径的 HTTP(S) URL，operation 必须留在 /mate-service/ 下，拒绝规范化点段，并满足模板占位符约束。

后续修订：2026-08-28 的 ADR-0035 废止了上述安装脚本兼容条款； 当时的部署必须直接设置 CAMPUSMATE_BASE_URL。2026-09-01 的 ADR-0042 后续只为公司镜像 增加本地缺省值；通用主模块仍要求显式设置。其余共享配置决策保持有效。

备选方案

方案优点拒绝原因
保留三个 base URL迁移最少继续允许同一服务被配置为不同 origin，服务身份没有收敛。
新旧键长期双读短期兼容旧部署优先级和冲突规则复杂，拼写错误成为长期公共契约。
只统一 base URL，路径仍分散改动较小重复 Skill operation 仍存在，无法形成可审计的调用目录。
共享 base URL + 六 operation 目录一个服务身份、一个来源、可启动期校验需要一次性迁移环境变量和配置键；本决策选择此方案。

明确不做

  • 不修改任何 CampusMate HTTP method、path、请求体、响应体、SSE 或认证规则。
  • 不把 Provider ID mate-model-manager 改名；model 仅是配置分组。
  • 不在应用内保留旧配置别名或根据空值猜测优先级。
  • 不把客户端超时、模型 token 参数或 Runtime 文件目录合并为共享参数。

后果与相关资料

正面后果：三个客户端必然指向同一服务 origin；Endpoint 可按 operation 清点；Skill query 不再重复；错误地址和越界 path 在启动阶段失败。迁移成本：通用主模块部署必须设置 CAMPUSMATE_BASE_URL，公司镜像未设置时使用 ADR-0042 定义的本地缺省值；旧应用配置键 不再生效，手工维护的交付 properties 必须同步。

外部设计基线：/Users/z/设计 的 c250e3f07536871d3d676242e552a5eb4346b0c7；详细实现与源码证据见 CampusMate 客户端共享配置设计。 Model Chat 的协议决策仍见 ADR-0025； 旧部署变量兼容的后续修订见 ADR-0035；公司镜像本地缺省值见 ADR-0042。
