Context

变更前源码从 POST Events 捕获 X-HW-ID、X-HW-APPKEY、Authorization 三项瞬态值，并把同一快照传给 Agent binding、Skill binding、tool metadata 和 tool execute。新的接口契约还要求 POST Events 接收精确命名的 access-token，同时明确凭据只允许在实际工具调用时向下游透传。

Runtime 不是这些凭据的认证权威。它需要保持现有集成边界：捕获收到的值、按执行隔离、不得持久化或记录秘密，也不得因为 Header 组合或 Bearer 形状增加本地认证错误。

Decision drivers

  • 把敏感 Header 的出站范围缩到真正需要认证授权的 execute operation。
  • 让“发现无凭据”成为 Java 方法签名可证明、测试可回归的边界。
  • 保留 Runtime、Child 与 Cron 已有的显式执行快照和生命周期隔离。
  • 保持 AppKey、JWT 或二者共存的上游组合，不在 Runtime 重复 Mate 的认证职责。

Considered options

继续让发现与执行共享四项快照

优点：内部签名改动少。
缺点：将秘密发送给无需执行授权的 binding 和 metadata operation，违反最小暴露原则。拒绝。

只在 HTTP 实现中忽略发现凭据，保留发现方法参数

优点：调用方兼容性较好。
缺点：类型仍允许未来误用，测试替身也可能继续传播秘密。拒绝。

发现方法移除凭据参数，execute 显式接收四项快照

优点：边界由接口直接表达；Agent、Skill 和 metadata 发现无法获得执行快照；execute 仍可逐请求透传。
缺点：需要同步修改内部客户端、发现器和测试替身。接受。

Decision

  • POST /campusclaw-service/v1/sessions/{sessionId}/events 额外读取精确 Header access-token，与 X-HW-ID、X-HW-APPKEY、Authorization 组成不可变执行快照。
  • MateToolClient#listAgentTools 和 #listSkillTools 移除凭据参数；Agent binding、Skill binding、tool metadata 请求只发送普通 JSON Header。
  • 只有 POST /mate-service/v1/runtime/tools/{toolId}/execute 透传快照中收到的四项 Header。线上的 Header 名固定为小写连字符形式 access-token，不使用旧别名 X-Access-Token。
  • execute 完整性要求 access-token、X-HW-ID 以及 AppKey/JWT 至少一种非空。AppKey 与 JWT 同时存在时全部原样透传。
  • POST Events 不新增本地鉴权拒绝。缺少执行凭据时 Session 仍可建立并使用无凭据发现；真正调用工具时 fail closed。
  • 快照只存在于活动执行内存；Child 继承父快照，Cron 没有入站快照；所有诊断继续只记录存在性，不记录值。

Intentional differences

接口契约变更：POST Events 比变更前多捕获 access-token。

安全加固：发现链路从“收到就透传”改为完全不能接收执行凭据，秘密只到达 execute operation。

架构保持：不增加 resolver、ThreadLocal、持久化凭据或 Runtime 认证器；真实性与动作授权仍由 Mate 决定。

Consequences

  • 正面：发现请求泄露执行凭据的路径被接口和聚焦 HTTP 测试同时关闭。
  • 正面：四项快照继续按 Session/Child 显式传递，共享客户端保持无状态。
  • 负面：没有 access-token 的旧调用方仍能提交 Events，但在执行 Mate 工具时会得到 unavailable/fail-closed 结果。
  • 后续：若某个发现 operation 将来确实需要独立认证，必须定义专用最小凭据，而不能重新复用工具执行快照。

Validation

  • RuntimeRequestContextTest 覆盖四项捕获以及缺少 access-token 时不本地拒绝但 execute 快照不完整。
  • HttpMateToolClientTest 覆盖 Agent/Skill/metadata 无四项 Header、execute 精确透传四项 Header、旧 X-Access-Token 不发送。
  • RuntimeEventRoutesTest 覆盖 POST Events 将 access-token 纳入提交给 Service 的快照。
