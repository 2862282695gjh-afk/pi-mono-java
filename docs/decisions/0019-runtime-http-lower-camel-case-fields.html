ADR-0019 · Runtime HTTP 公共字段统一使用 lowerCamelCase

Status: Accepted · Date: 2026-08-21 · 设计文档: coding-agent-cli · 实现分析基线: 304eda06ff603fc9b6bbcaad0c296cc151a7defb · 契约基线: pi-mono-java-design@cee69de250a6cf796c55aa1ba591e7f85775713d

Context

HTTP 1.37 实现的 Path 变量、请求/响应 VO 和 SSE data 使用了 session_id、file_ids、entry_seq 等 snake_case 字段。独立设计仓库的 HTTP 1.38 契约已经确认，CampusClaw 公共 Path、Query、JSON 与 SSE data 字段统一使用 lowerCamelCase，请求头保持原名。

源码证据包括四个 Runtime Controller、请求与响应 VO、RuntimeEntryCodec#toSseData、RuntimeEntryCodec#toHistoryEvent 和 RuntimeEventProjector。数据库列、MyBatis 映射和既有 Entry payload 是内部持久化格式，不等于公共 wire field。

Options considered

  • 继续公开 snake_case
    Pro：不修改当前调用方。
    Con：与已确认的 1.38 契约和 Java 默认命名不一致。Rejected。
  • 同时接受 snake_case 与 lowerCamelCase
    Pro：客户端可渐进迁移。
    Con：形成双别名、未知字段和签名输入歧义，长期扩大测试矩阵。Rejected。
  • 公共边界仅使用 lowerCamelCase，内部持久化保持兼容
    Pro：公共契约单一；既有 Entry 无需迁移；工具参数不被误改名。
    Con：Entry 输出需要显式投影。Chosen。

Decision

  • 所有 Runtime Path 变量、Query 参数、JSON 请求、普通 JSON 响应和 SSE data 字段使用 lowerCamelCase。
  • X-HW-ID、Authorization、X-HW-APPKEY、If-Match、Accept-Language、Content-Language 等 Header 保持原名。
  • 事件类型、错误码、tool_call 等枚举值和类型化 ID 值保持不变。
  • 请求 VO 只接收 lowerCamelCase，不提供 snake_case 别名；严格 JSON 类型检查继续由对应请求 VO 承担。
  • 数据库列、MyBatis 映射和既有 Entry payload 可以保持内部 snake_case。RuntimeEntryCodec 按事件类型显式投影公共字段，并保留工具 arguments 的原始键。

Consequences

  • 客户端：旧 snake_case 请求字段按未知字段拒绝，调用方必须原子升级到 1.38 字段名。
  • 路由：Controller 的 @PathVariable 名称和异常分类同步改为 agentId、sessionId。
  • 响应：Session、模型、控制消息、分页事件和全部 SSE payload 只输出 lowerCamelCase。
  • 数据：不要求迁移已有 Entry payload；受控投影保证旧记录也只以 lowerCamelCase 暴露。
  • 验证：路由、事件投影、分页和跨进程测试同时断言 lowerCamelCase 输出与 snake_case 请求拒绝。
