ADR-0018 · 对齐 Runtime HTTP 1.37 资源与 thinking 契约

Status: Accepted · Date: 2026-08-20 · 设计文档: coding-agent-cli · 基线: origin/main@3d9b9c55569486f024d6a507ce004101a56dee3f

Context

独立 HTTP 设计仓库的 1.37 契约要求 Agent、Tool、Skill、Session 使用类型前缀加去连字符 UUID；新 Session 默认 thinking=true；提交用户消息的 operation 已固定为 user.message，请求体不再重复携带 type。

分析基线仍由认证拦截器在进入 Controller 前检查 X-HW-ID 与 JWT/APPKEY 的齐全、共存和 Bearer 形状，并定义两个本地认证错误码。基线也只公开 Assistant 文本事件：Provider 已有 thinking start/delta/end，但 Runtime 未投影或持久化。

基线源码证据包括 RuntimeApiConstants、MateServiceClient#getAgentRuntime、AgentRuntimeManager#prepare、RandomSessionIdGenerator#nextId、RuntimeSessionService#newSession、RuntimeAuthenticationInterceptor#preHandle、UserEventRequestVO、AssistantMessageEvent、RuntimeEventProjector#projectMessageUpdate、RuntimeEventQueryService#list 与 RuntimeSessionMapper.xml#listCurrentBranch。当前分支落地证据新增 common/identifier/ResourceIdentifierPatterns.java；这是目标设计的实现，不是 pi 或分析基线的既有行为。

Options considered

  • 继续由 Runtime 校验两种凭据组合
    Pro：缺失 Header 可在本服务立即失败。
    Con：重复上游认证职责，且与“Header 可共存、不检查组合”的确认契约冲突。Rejected。
  • 只增加 thinking 实时 SSE，不持久化
    Pro：实现简单。
    Con：断线后 GET 无法恢复已开放的完整 thinking，POST 与 GET 的权威事件集合不一致。Rejected。
  • 上游认证 + thinking completed 独立持久化 Entry
    Pro：Runtime 无凭据状态；实时与恢复语义一致；关闭可见性不破坏历史。
    Con：分页查询和游标必须绑定 thinking 状态，持久化序列多一种 Entry。Chosen。

Decision

  • 全部 11 项 operation 继续把 X-HW-ID、Authorization 或 X-HW-APPKEY 作为集成调用上下文；Runtime 不检查缺失、共存、格式或真实性，不创建认证上下文，也不定义 UNAUTHENTICATED 和 AUTH_CREDENTIAL_CONFLICT。
  • Agent、Tool、Skill、Session ID 分别使用 agent-、tool-、skill-、session- 加 32 位十六进制 UUID；Session 生成器输出小写十六进制，新 Session 持久化 thinking=true。
  • 四类资源 ID 的正则字符串与编译后的 Pattern 集中在中立的 ResourceIdentifierPatterns；RuntimeApiConstants 只保留 HTTP 路径、模型格式和请求上限。
  • POST /events 请求 VO 只声明 message 与 file_ids；旧 type 按未知字段拒绝。
  • 执行接受时把 Session thinking 固化在进程内 holder。快照为 true 时投影 assistant.thinking.started/delta/completed，其中 completed 作为独立 Entry 持久化；快照为 false 时三类事件均不产生。
  • GET /events 按查询时 Session 当前 thinking 决定是否把 assistant.thinking.completed 加入当前分支结果。关闭只隐藏、不删除。page 加密绑定 Session、继续位置、thinking 和过期时间；开关变化使旧 page 无效。
  • Assistant MessageEntry 继续过滤 ThinkingContent，模型历史恢复也不把公共 thinking Entry 重新注入消息，避免重复内容和推理提示污染。

Consequences

  • 安全边界：Runtime 不再产生本地凭据判断；上游必须在调用前完成真实性和动作授权。Header 不落库、不进 Prompt、不进 Event。
  • 数据：t_sessions.agent_id 扩为 VARCHAR(64)；t_session_entries.type 已能容纳新事件名，不增加表。完整安装 DDL 随实现更新。
  • 分页：thinking 过滤在 SQL 的 LIMIT 前完成，避免隐藏事件占用页大小；状态切换后客户端必须从第一页重读。
  • 兼容：旧 Agent/Session ID、消息体 type 和旧 page 不兼容；这是已确认的 V1 契约收敛，不提供别名。
  • 依赖：核心运行时和 Mate 客户端复用同一组领域模式，不再分别编译正则，也不再为了资源约束依赖 HTTP API 包。
  • 验证：单元与路由测试覆盖类型化 ID、默认 thinking、Header 缺失/共存、旧 type 拒绝、thinking 开关投影、持久化过滤和游标失效；openGauss 集成测试覆盖四类当前分支 Entry。
