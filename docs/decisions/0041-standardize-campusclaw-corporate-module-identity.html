ADR-0041：统一 CampusClaw 公司镜像模块身份

Status：Accepted

Date：2026-09-01

Source baseline：98d3999ec6d57e099d7bf02aaa4fcf9607fc61aa

文中的仓库路径按当前模块身份展示；源码基线 SHA 是迁移前行为证据。

Context

仓库以四个根 Reactor 模块维护通用业务源码，同时生成一个面向公司环境的单模块镜像。 公司集成要求统一模块目录、Java 包、Maven 坐标、启动类和产物名，并切换到公司 NativeParent。根 Reactor 必须继续在普通开发环境独立构建。

Decision

项目决策值
目录campusclaw/
Java 根包com.huawei.hicampus.claw
Parentcom.huawei.hicampus:NativeParent:26.0.0-SNAPSHOT，并使用空 relativePath
项目 GAVcom.huawei.campus:claw:1.0-SNAPSHOT
默认产物claw-1.0-SNAPSHOT.jar
应用身份campusclaw；启动类 com.huawei.hicampus.claw.codingagent.CampusClawApplication
同步入口scripts/sync-campusclaw.sh

公司镜像不加入根 Reactor，不配置 finalName，也不提供旧目录、脚本、包、坐标或 产物名的兼容入口。同步脚本默认解析公司父 POM 并验证镜像；普通环境只能显式使用 --no-verify。

考虑过的选项及取舍

选项 A：一次性统一身份并保持独立构建（选择）

Pro：公司模块身份单一，GAV 与默认 JAR 一致；根 Reactor 不依赖公司仓库； 包扫描、日志和白名单只有一个目标。

Con：公司父工程及部署配置必须同步迁移，无法分阶段依赖旧入口。

选项 B：保留兼容目录、包或产物别名

Pro：外部使用方可渐进迁移。

Con：会形成重复包扫描、脚本分叉和产物身份歧义，并延长不可验证的兼容期。

选项 C：把公司镜像加入根 Reactor

Pro：一次 Maven 命令可覆盖所有模块。

Con：普通开发构建会被公司父 POM 和仓库可用性阻塞，破坏通用工程边界。

所选方案与理由

选择选项 A。单向生成继续保证业务源码只有一个权威，公司 POM 和环境专有文件留在镜像 边界；空 relativePath 强制使用公司仓库父 POM。默认验证失败时显式报错，防止把 未执行的公司构建误报为成功。

Consequences

  • 正向：目录、Java 包、GAV、启动类、日志分类和默认 JAR 统一。
  • 正向：根工程构建与公司镜像构建保持独立，失败归因清晰。
  • 负向：公司 Maven 环境之外不能完成镜像最终构建门禁。
  • 后续：公司父工程必须更新模块路径、GAV、JAR、启动类、包扫描和白名单。
  • 门禁：公司环境验证通过前，相关 Draft PR 不得转为 Ready 或合并。
