Context

基线实现把复制动作放在每个 AssistantRichText 内，并为每个 fenced code block 再提供一个文字按钮。一次用户请求可能经历多个 Assistant Entry 和工具循环，因此产品界面会出现多个“复制原文”和“复制”按钮；这些按钮既显眼，又把 Runtime 的消息切分泄漏成用户交互。

ThinkingDisclosure.vue 只有存在安全摘要时才渲染为 <details>。当前 Runtime 没有安全摘要字段时，它退化为不可点击状态，用户会把“无法展开”理解为界面故障。Thinking 与 Tool 同时直接放在主画布背景上，缺少区别于最终回答的轻量分组。

0.8.0 把连续 Thinking/Tool 放入同一个虚线活动组。真实失败场景中，一个展开工具会把前后多个 Thinking 一起包入巨型容器，单项边界不清晰。用户在 PR #178 合入后明确要求保留现有暖灰、虚线和圆角样式，但让 Thinking 与每个 Tool 分别拥有独立框。

Decision drivers

  • 用户认知中的复制对象是一次提问对应的整轮回答，不是单条 Runtime Entry 或代码 fence。
  • 复制动作应像 Codex 对话动作一样使用小图标和透明命中区，默认低强调。
  • 分析入口必须稳定可发现，同时继续禁止原始 thinking 进入 DOM。
  • 分析与工具需要共同的视觉边界，但不能变成厚重卡片或监控 Dashboard。
  • 每个活动需要独立边界，避免一个长工具详情改变相邻 Thinking 的视觉归属。

Considered options

保留消息级与代码块级复制，只缩小按钮

Pro：改动最小，仍可单独复制代码。
Con：一轮多个入口的问题没有解决，仍暴露内部 Entry 切分。拒绝。

只在最后一个 Assistant Entry 下显示复制

Pro：界面上只有一个按钮。
Con：只复制最后一段会遗漏工具循环前的 Assistant 文本；按钮位置与复制内容语义不一致。拒绝。

按 User turn 聚合 Agent 回合并提供单一动作

Pro：复制范围符合用户认知；同一结构可统一 O1、活动分组和运行状态。
Con：需要增加前端回合投影，并明确运行中隐藏复制的规则。接受。

没有安全摘要时继续禁用分析展开

Pro：不会展示无内容面板。
Con：同一控件在不同部署下行为不稳定，且用户无法区分安全降级与故障。拒绝。

连续 Thinking/Tool 共用一个虚线活动组

Pro：时序紧凑，外框数量少。
Con：展开工具会形成过大的组合卡片，相邻 Thinking 和 Tool 的归属不清晰。0.8.0 曾采用，用户评审后拒绝。

Thinking 与每个 Tool 分别使用独立虚线框

Pro：保留现有视觉语言，同时让每项活动可独立扫描、展开和定位。
Con：相邻活动之间会增加 10 px 垂直间距。接受。

Decision

  • conversationRounds.ts 以 User turn 为边界，将其后的 Assistant、Thinking 与 Tool turn 聚合为一个 Agent round；刷新历史与实时流使用相同规则。
  • 同一 Agent round 中每个 Thinking 与 Tool 分别形成一个活动块；每个活动块使用 --surface-secondary 暖灰背景、--border-strong 1 px 虚线和 12 px 圆角，相邻框间隔 10 px。视觉参考开发者诊断入口但不复用其诊断语义。
  • Thinking 始终使用原生 <details>。运行中默认展开，完成后默认折叠；有 display 摘要时显示摘要。完全没有 Thinking 事件时不创建分析框；收到事件但缺少 display 摘要时，运行中显示“分析进行中，暂未收到面向用户的摘要”，完成后显示“已收到分析事件，但当前环境未提供面向用户的摘要”。原始 delta/content 仍禁止进入 DOM。
  • 移除 Assistant 消息级“复制原文”和代码块级复制按钮。每个完成的 Agent round 只显示一个复制图标；当前 round 仍在 streaming、thinking 或执行工具时隐藏。
  • 复制内容是本轮全部非空 Assistant rawMarkdown，按原 Entry 顺序用两个换行连接；不包含 Thinking 摘要、工具参数、工具结果或错误诊断。
  • 复制按钮使用透明 44 × 44 px 命中区和 17 px 图标；默认低强调，round hover、键盘 focus 或无 hover 设备上可见。成功后切换 check 图标，并通过 tooltip、aria-label 和 live region 提供反馈。

Intentional differences

产品约束：代码块不再提供独立复制动作；需要单独代码时用户仍可选择文本，产品优先保证一轮一个清晰复制入口。

安全加固：可展开不意味着可以读取原始思维。收到事件但 display 摘要缺失时只显示精确产品占位，公共 bridge 仍负责生成可展示摘要。

架构变化：UI 新增 User-turn-to-Agent-round 投影。Runtime Event 与持久化 Entry 契约不变，回合只存在于前端产品视图。

Consequences

正面：每轮回答只有一个低噪音动作；分析入口行为稳定；每个 Thinking/Tool 的边界清晰；O1 只在 round 顶部出现一次。

负面：单独复制 code fence 不再是一键操作；多 Assistant Entry 复制时会插入两个换行；相邻活动框增加少量垂直间距；运行中必须等待 round 完成后才能使用复制按钮。

后续：公共 Chat 契约如未来提供稳定 turn/round ID，前端聚合键可从 User Entry 边界迁移到公共 ID，但复制范围与安全边界保持不变。

Validation

  • conversationRounds.test.ts覆盖 User 边界、活动逐项独立、多 Assistant 聚合和运行状态；runtimeEventProjector.test.ts区分没有 Thinking 事件与有事件但无 display 摘要。
  • 浏览器验收覆盖分析展开、精确占位、完成 round 的单一复制按钮、复制文本、Thinking/Tool 独立虚线边界和桌面/移动视口。
  • 前端必须通过 npm test、npm run typecheck、npm run build 和高危依赖审计。
