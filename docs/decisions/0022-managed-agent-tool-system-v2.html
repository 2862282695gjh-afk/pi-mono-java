ADR-0022 · 受管 Agent 使用三入口八工具关闭集合

Status: Accepted · Date: 2026-08-24 · Design: tool-system-v2

Context

基线实现同时存在 CLI、动态 ToolCatalog/Extension、本地写与命令工具、两套 Child Agent 调用方式，以及依赖预先 List 的 Mate 调用。对于 ToB 受管 Agent，这会让模型实际可见的工具 随 Spring classpath 和入口发生漂移；本地文件工具还能观察进程可见路径，无法形成 Agent 租户边界。

Decision

选定：公共工具名关闭为 Read、Find、 Grep、Ls、Cron、ListMateTools、 CallMateTool、Agent；入口关闭为 Runtime、Cron、Child Agent。
  • 三个入口都通过公共 AgentSessionFactory 创建隔离 Session，Host 单独持有生命周期。
  • 四个本地读取工具只能访问当前 agent/{agentId}，拒绝符号链接和 realpath 越界。
  • Mate 工具由模型按名称直接调用；Session cache miss 时 single-flight 自动发现完整绑定集，只重试发现。
  • Agent 只解析直接绑定，首版最大深度 1；Child 仍使用公共 SessionFactory。
  • Cron 只在 Runtime 管理，Job 绑定 Agent，触发时使用 Agent 当前目录和 cron profile。
  • CLI profile、Loop、Bash/Edit/Write 模型入口以及动态目录不提供兼容别名。

Options

方案优点代价
保留动态 ToolCatalog旧 Extension 继续即插即用模型契约不可稳定审计，入口和 Session 易出现不同工具集
每入口维护独立 Session短期改动少hook、取消、错误、模型和 Child 行为持续分叉
关闭集合 + 公共 SessionFactory契约稳定、隔离明确、入口一致旧 CLI/Extension/工具名硬切换
Call 要求 scope/Skill 参数无需同名冲突检测把内部绑定来源泄漏给模型，调用前仍需人为选择来源

Consequences

  • 正面：启动时即可证明工具名和 profile；文件读取具备 Agent 边界；父子与定时执行共享相同语义。
  • 正面：Mate List 保持实时，Call 具备缓存快路径和 miss 自愈，并避免副作用重放。
  • 负面：旧 CLI、Extension、旧 Cron payload 和旧小写工具名不兼容；部署配置必须一次性切换。
  • 边界：Cron 集群持久化与租约不由本 ADR 决定；旧底层工具代码可暂存但必须保持模型不可达。

Supersedes

本 ADR 取代 ADR-0011 中“按需激活 Skill 工具”的模型入口、ADR-0014 的旧 Child Agent 执行工具，以及 ADR-0015 中继续保留本地 ToolCatalog 的结论。Mate 按调用解析凭据的 ADR-0021 继续有效。
