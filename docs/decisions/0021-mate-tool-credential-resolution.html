ADR-0021 · Mate 工具执行凭据按调用解析与 fail-closed 默认

Status: Accepted · Date: 2026-08-22 · 设计文档: mate-tool-client · 关联: ADR-0011

Context

CallMateTool 的执行 RPC 接通后，凭据来源成为链路的最后缺口。 约束：MateToolClient 是进程级 Spring 单例，横跨所有会话——凭据若缓存在实例字段会跨会话串用； AgentTool.execute 契约（toolCallId/params/signal/onUpdate）不携带任何请求身份， AgentLoop 层没有凭据通道。HTTP 入口捕获凭据与异步执行时的跨线程传播属上层职责，不在本客户端范围。

Decision

采用按调用解析 + fail-closed 默认：

  • MateCredentialResolver 接口由部署方注册为 Spring Bean； CallMateTool 每次调用以 MateToolCall(toolCallId, tool, args) 只读快照（JSON 深拷贝 + 逐层 unmodifiable）委托解析，按调用隔离、无实例状态。
  • MateCredentials.isComplete()：X-HW-ID 非空白 且 AppKey/JWT 恰好其一非空白； jwt() 工厂拒绝空 token。残缺凭据在请求发出前拒绝（零请求）。
  • 未注册 resolver 时 resolveCredentials() 返回 null， invokeTool 拒绝执行并报错指向接线方式——未接线绝不伪装成匿名/半认证调用。

考虑过的选项

选项ProCon
AgentTool 契约扩展传凭据最显式需改 core 组件（越界）；23 个实现类全动
ThreadLocal 请求上下文不动接口隐式传播；并行/异步工具调用易漏；依赖线程模型假设
按调用 resolver（选定）不动 core；显式接线点；测试可注入需要部署方实现一个 Bean；上下文受限于 execute 签名
配置文件静态凭据零代码所有会话共享同一身份，与按调用隔离矛盾

Consequences

  • 正面：无凭据时快速失败且报错可操作；并发会话凭据隔离有测试保证（40 线程交替调用零串扰）； 嵌套参数防篡改（深拷贝 + 全层只读）。
  • 负面/后续：部署方必须实现 resolver 才具备执行能力（DEF-007 剩余项）； 会话粒度身份（AgentContext/会话 ID）不在快照内——若 core 未来扩展契约，可直接增补。
