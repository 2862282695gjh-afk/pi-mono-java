Context

既有 Model PUT 先检查 If-Match，并在数据库行锁下重检同一版本。它可以安全使用锁前生成的领域 Entry； Command 不携带该条件，若只把 expectedVersion 改为可空，事件可能记录陈旧的 previousModelId， 或漏掉并发开启 Thinking 后应追加的自动关闭事件。

Java 源根为 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/runtimeapi/。 基线证据为 session/RuntimeSessionConfigurationService.java:changeModel/modelChangeEntries 与 persistence/MyBatisRuntimeSessionRepository.java:updateModel/rejectConfigurationUpdate。

选项及取舍

  • 复制一套 Command 配置事务：入口独立，但会分裂条件更新、能力和历史规则，不采用。
  • 只取消 expectedVersion：代码少，但丢失保护锁前事件的条件，不采用。
  • 共享窄服务与事务，锁内调用本地事件工厂：增加一个函数参数，但同一事务负责权威旧值和序号，采用。

Decision 与理由

  • service.command.SessionModelConfigurationService 负责模型查询/切换； service.command.contributor.ModelCommandContributor 贡献准入和真实 Handler，不引入中央名称 switch。
  • Repository 的可选版本只放宽 Command；既有 PUT 和 RuntimeSessionModelReconciler.reconcile 继续传实际版本。状态与同值检查顺序不变，running 同值仍不能作为修改被接受。
  • Model Service 的 modelChangeEntries 作为本地工厂在锁内读取旧模型和 Thinking， 不执行网络请求。Model 更新失败时，配置、Entry、Sequence 和 active leaf 全部回滚。
  • 配置结果迁入 dto.SessionConfigurationUpdateDTO，携带最后实际追加的 Entry 序号； dto.command.ModelCommandResultDTO 只承载结果，HTTP VO 组装仍留给后续切片。
  • 查询/同值不产生 Entry；不创建 commandId、命令生命周期或 Name 历史。Spring 单例不保存请求和凭据。

pi 4af9d21d3b4d664e4a29fcabfec85171077248e3： packages/coding-agent/src/core/agent-session.ts:setModel/setThinkingLevel 验证凭据、保存模型并调整思考级别； packages/coding-agent/src/core/session-manager.ts:appendModelChange 按当前 leaf 追加。 Java 的 boolean Thinking、同模型不写入及 idle 修改限制属于产品约束，行锁和可选版本属于架构变化，不是 pi 的 HTTP 行为。

Consequences

  • 正面：Command 并发使用锁内最新值，旧 PUT 保留 428/412/ETag 行为，两者复用模型能力与事件语义。
  • 代价：同一 Session 的配置和其他数据库操作仍竞争一把行锁；工厂必须保持本地、短小且无外部副作用。
  • 范围：不改设计仓、不发布 Command HTTP、不增加升级脚本；Builtin/Skill 由用户统一负责集成， 共享入口验收不因本切片只实现 Model 而缩减。Thinking Handler 留待合并后下一独立 PR。
