ADR-0098：控制副作用提交前预留结果响应

Status: Accepted · Date: 2026-09-08 · Version: 1.0.0

Context

interrupt 与 tool confirmation 是不可通过网络失败安全重放的控制副作用。请求要先返回自身回执，再等待原执行的权威终态或新结果段。接受实例可能没有原 Agent，因此响应不能依赖本地事件监听。

Decision

在控制事务前按真实 HTTP 响应数量预留 waiter，并预编码、预检完整回执。事务成功后先把回执入队，再以固定 target 和回执序号绑定 waiter，随后异步触发与周期轮询相同的权威结果补读。complete、detach、容量溢出和超时通过流的一次性关闭动作注销等待。

考虑过的选项及取舍

  • 事务提交后再登记：实现顺序简单，但容量不足会留下客户端无法观察且不能安全重放的副作用，因此不采用。
  • 本机监听 Agent、远程实例补读数据库：本机延迟较低，但两条交付路径会产生不同语义和重复完整事件，因此不采用。
  • 一个 waiter 持有 Holder 和凭据：恢复直接，但扩大资源生命周期和泄露边界，因此不采用。
  • 选择固定 target 的权威补读，代价是增加有界登记、异步通知和周期查询。

Consequences

本机与跨实例响应具有相同完整事件来源；回执保持首帧，确认段和根执行采用不同终点。受理后流失败不回滚已提交控制，超时只结束观察。等待和通知都有容量上限及失败退避。没有新增 Maven 依赖。

HTTP 状态与验证

Control 单片提供内部应用 Service，尚未切换生产 Controller。实现提交 c70cc57f 的聚焦命令执行 33 项单元测试，其中控制受理直接测试 5 项，其余验证流、工厂、waiter、poller 和消息回归；跨 JVM HTTP 验收由 ADR-0099 的统一接入片负责。
