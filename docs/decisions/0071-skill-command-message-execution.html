ADR-0071：Skill 复用普通消息执行

Status：Accepted · Date：2026-09-08 · Version：1.0.0

Context

用户于2026-09-08明确接受共享 Skill 请求方案，以及完整 Skill 说明与本次输入组合文本 发送模型、普通消息保存、随SSE/历史返回、按保存文本恢复。此决定补充设计 88f4df16bc24bbfcd28e1ec374feb2de0db8be3b 的旧待确认标记；本片不修改独立设计仓。

Java 基线 8d61c767d09d47ef6c8d76c05535fcbb58c48373 已有实际绑定准入和普通消息生命周期。 源码根为 modules/coding-agent-cli/src/main/java/com/campusclaw/codingagent/： session/AgentSessionFactory.java#create 一次prepare后复用同一runtime； runtimeapi/event/RuntimeEventService.java#acceptUserEntry 保存普通消息， runtimeapi/event/RuntimeEntryCodec.java 负责公开投影与恢复。

pi 4af9d21d3b4d664e4a29fcabfec85171077248e3 的 packages/coding-agent/src/core/agent-session.ts#_expandSkillCommand 是本地展开行为， 会去frontmatter并加入本地路径；Java保留受管缓存完整说明且不添加路径，不复制未知命令回退。

Decision 与选项

  • 采用同次实际快照展开：Skill服务提供无外部副作用的输入函数，在工厂准入回调中 检查直接绑定并组合正文。优点是准入、正文和实际Agent同源；代价是输入准备需要进入现有受管工厂流程。
  • 采用单份普通消息：同一文本交给模型、Repository、SSE和历史恢复。 优点是无需新存储或恢复协议；代价是具有Session读取权限的客户端能看见完整Skill说明，这已获用户确认。
  • 不先展开旧缓存再提交：实现表面简单，但第二次prepare可能得到不同绑定或正文，不能保证同源。
  • 不建立第二份私有正文快照：可实现展示与执行分离，但带来额外保留期和恢复规则，既无需要也未获授权。

Consequences

复用原操作锁、容量、Holder、超时、Projector和收尾，Spring单例不存请求状态。 原始参数和实际展开消息均受262144个UTF-16单元约束；附件最多32项且唯一、保序。 Skill name-only允许执行；错误不回退普通输入，不向消息人为添加服务器路径或凭据。

原模型纠正可能先保存Model/Thinking领域Entry，保留该语义；绑定或展开失败不接受新的用户消息、 不启动模型，并释放准备期间资源。数据库竞争方状态不能被失败请求清理。

后续共享POST负责严格联合请求VO、Header处理、Builtin JSON与Skill普通SSE分流及真实HTTP验收。 本片不发布路由、不迁移Events v2、不增加commandId、通用命令生命周期、升级脚本或私有快照。

Validation

单元测试覆盖归一化、错误和消息边界；openGauss专项使用真实公共工厂、Agent、Repository及执行协调， 覆盖同次正文的模型/保存/SSE/历史/重连恢复，以及detach、准入、容量和接受竞争。 具体命令及完成结果见下方实现说明，不将内部服务测试表述为共享HTTP验收。
