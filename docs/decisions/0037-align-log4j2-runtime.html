Context

变更前，仓库通过根 POM 为全部模块直接选择 Logback，Spring Boot Starter 也保留默认日志实现。公司环境的父 POM 会引入 Actuator 和日志自动配置；根据本次启动异常，该外部配置要求原生 Log4j2 Core LoggerContext，而混合日志 Classpath 提供了不兼容的上下文类型，导致启动期类型转换失败。

公司父 POM 和自动配置源码不在当前仓库，以上内容是外部集成条件，不是本仓库源码观察。Windows 只是发生异常的环境，根因是 Java 依赖图，与 Windows 平台 API 无关。

Decision drivers

  • 与公司 Actuator/日志自动配置使用同一种 Log4j2 Core 上下文。
  • 生产、测试和 campusclaw 只保留一个 SLF4J Provider。
  • 不修改公司父 POM，也不以逐项排除 Actuator 替代日志运行时对齐；管理面关闭由 ADR-0038 独立决策。
  • 保留现有 SLF4J 业务日志调用和结构化字段。

Considered options

继续使用 Logback，并排除公司 Actuator 或日志自动配置

优点：仓库改动较少。
缺点：偏离公司受管运行环境，需要持续追踪父 POM 的传递依赖和自动配置，且不能解决其他 Log4j2 组件的上下文预期。拒绝。

生产使用 Log4j2，测试继续使用 Logback

优点：现有日志测试改动较少。
缺点：测试不再覆盖实际运行时绑定，仍可能隐藏多 Provider 或桥接冲突。拒绝。

生产、测试和镜像统一使用 Log4j2

优点：依赖图和事件模型一致，满足公司环境的原生 Log4j2 Core 预期。
缺点：需要迁移 Logback 专用测试，并改为断言 Log4j2 的 ContextData 和 Throwable。接受。

Decision

  • 根 POM 用 spring-boot-starter-log4j2 替换直接的 logback-classic。
  • 所有直接引入 Spring Boot 主 Starter 或测试 Starter 的相关模块排除 spring-boot-starter-logging。
  • 目标依赖树和可执行 JAR 不得包含 logback-classic、logback-core 或 log4j-to-slf4j。
  • 测试使用 test-scope Log4j2 Appender，直接验证格式化消息、级别、ContextData 和 Throwable。
  • campusclaw 保持与模块源码同步，并在其独立 POM 应用同一日志排除。
  • campusclaw 使用独立公司父 POM 时，在自身 POM 显式声明 slf4j-api 和 spring-boot-starter-log4j2；公司父 POM 管理版本但不代替 应用声明所需依赖。

后续实施修正：2026-09-01 切换到 NativeParent 后，公司镜像不再继承 根 POM 的公共日志依赖，但镜像 POM 一度只保留默认日志排除，导致公司构建在测试编译阶段报告 org.apache.logging.log4j 不存在。本次显式依赖修复恢复本 ADR 已接受的目标 Classpath， 不构成新的架构决策。

Intentional difference

架构变化：日志后端从 Logback 切换为 Log4j2，生产和测试共享同一事件模型。产品约束：无业务 API 或日志字段变化。公司集成约束：应用 Classpath 必须满足公司 Actuator/日志自动配置的原生 Log4j2 上下文预期；管理 Web 面关闭另见 ADR-0038。

Consequences

  • 正面：消除双日志实现、双向桥和不兼容 LoggerContext。
  • 正面：主工程、镜像和测试的日志行为由同一实现验证。
  • 正面：公司镜像不再依赖根 POM 或公司父 POM 隐式带入日志实现，Maven 构建边界清晰。
  • 负面：控制台默认排版可能与 Logback 不同，结构化字段的展示由部署 Layout 决定。
  • 边界：未新增 log4j2.xml，日志级别和输出格式仍由 Spring Boot 或部署环境配置。
  • 边界：本决策不新增 Windows 启动或安装支持。

Validation

  • 主工程和 campusclaw 分别执行完整 Maven verify。
  • 检查两侧依赖树，只允许 log4j-slf4j2-impl 作为 SLF4J Provider。
  • 公司镜像依赖树必须包含 slf4j-api、log4j-api、log4j-core、 log4j-slf4j2-impl 和 log4j-jul。
  • 检查两个可执行 JAR 的 BOOT-INF/lib，确认没有 Logback 和反向桥。
  • 日志相关测试直接覆盖 WARN/ERROR、结构化字段、异常对象和敏感信息不泄漏。
  • 执行镜像 dry-run、PlantUML 生成、文档链接、ASCII、XML 和 Git diff 校验。
