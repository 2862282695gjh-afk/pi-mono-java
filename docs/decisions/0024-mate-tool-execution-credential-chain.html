ADR-0024 · Mate 工具使用执行级显式凭据链

Status: Accepted · Date: 2026-08-24 · Design: mate-tool-client · Supersedes: ADR-0021 · Refined by: ADR-0032

Context

实现基线 934b5dd7d9e50b1d7359bea5f2dda71e3c4a34ac 中， CallMateTool 依赖可选 MateCredentialResolver Bean，但仓库没有实现； Runtime Controller 收到的调用上下文 Header 只用于契约测试，没有进入 Session 或工具。 ListMateTools 也始终构造空 Header。结果是执行 RPC 默认 fail closed，部署方占位 无法证明 Runtime、Child 或 Cron 的凭据来源与隔离。

Decision

本节记录 2026-08-24 的原始决策；当前发现/执行 Header 边界以 ADR-0032 为准。

  • 删除可选 resolver；POST Events 从三项 Header 创建不可变 MateCredentials，经 Service、Registry、SessionRequest、SessionFactory 显式传递。
  • 同一 Session 的 List 与 Call 使用 POST Events 读取的相同凭据值；Agent/Skill/metadata 发现请求也发送非空值。
  • Child 使用父执行持有的凭据值；Cron 没有入站调用方时不持有这些值，List 可访问免认证发现端点， Call 在发现或执行请求前 fail closed。
  • Runtime 不验证真实性，不在 AppKey/JWT 同时存在时选择或拒绝；执行只要求 X-HW-ID 与至少一种下游凭据，最终认证授权由 Mate 完成。
  • 这些值只在本次 Agent 执行及其 Child 调用期间由内存对象持有，不持久化、不进入 Prompt/Event/日志； 执行结束后 Runtime 不再主动持有，诊断字符串必须脱敏。

考虑过的选项

选项优点缺点
部署方 resolver核心改动少仓库默认不可用，依赖线程或请求作用域隐式传播
ThreadLocal方法签名短异步、虚拟线程和 Child 传播容易丢失或串用
执行期间内存对象来源、持有时段和 Child 使用行为可测试；共享客户端无状态需要调整内部方法签名
进程级静态凭据Cron 可直接使用所有 Agent 共用身份，违反按执行隔离

Consequences

  • 正面：Runtime 到两个 Mate 工具的完整链路由仓库自身实现并可分段验证。
  • 正面：Child 不依赖 Servlet 线程；凭据不会跨 Session 缓存或被单例客户端保存。
  • 负面：Cron 的 Call 能力在没有独立 Agent/service credential source 时保持 unavailable。
  • 后续：若 Cron 需要执行 Mate 工具，应另行设计按 Agent 获取的短期服务凭据，不得回退为全局静态密钥。
