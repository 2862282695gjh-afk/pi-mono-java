常规对话 常规对话 idleConversation 已实现 · 过渡 adapter

作用

围绕 Agent、Chat、消息、附件和工具活动完成日常任务。协议身份、ETag、原始 SSE 和凭据不进入产品主流程。

主要评审点

  • 安全的思考摘要与工具是否在同一 Agent 活动区中易于连续阅读，又保持独立信任边界。
  • 工具详情是否按输入在上、输出在下阅读，并且不显示内部 ID、绝对路径或凭据。
  • Assistant-only 安全 Markdown 与 User/Thinking/Tool 专用 viewer 边界是否清楚。
  • 表格和代码块是否只在自身容器横向滚动，不撑破对话区。

执行中控制 执行中 runningConversation 已实现 · HTTP 1.38.0

作用

让用户看懂 Agent 正在做什么，并通过“调整方向”“加入队列”“停止”控制唯一 active execution。

主要评审点

  • 运行中分析摘要是否足够可读，同时不暴露原始私有推理。
  • 当前工具展开、完成工具折叠和未开始工具不显示是否符合活动节奏。
  • 输入参数与输出结果的纵向顺序是否比左右分栏更易扫描。
  • 当前跟进方式是否在发送前足够清楚，且无需两个常驻胶囊。

本轮确认项

1. 已实现：三状态信息架构

firstUse、idleConversation、runningConversation 作为首版稳定评审和测试边界。

2. 已实现：O1 品牌标识与暖中性配色

O1 使用原始透明 PNG，不生成式重绘，也不缩进深色品牌方块；暖白、暖灰与深暖黑构成工作台，珊瑚色仅用于品牌标识，绿色继续表达运行与完成。

3. 已确认：跟进交互与 Codex desktop 一致

desktop 默认“调整方向”，设置可切换“加入队列”；Cmd/Ctrl+Shift+Enter 对单条消息临时反转。“调整方向”不会硬中断当前模型或工具。

4. 已实现：Assistant-only 安全富文本边界

Assistant 正文支持受限 Markdown；User 与 Tool 原始结果保持纯文本/专用 viewer，Thinking 只显示安全摘要或状态。raw HTML、远程 Markdown 图片、相对路由和危险协议永不激活。

5. 已实现：Codex-inspired 活动 disclosure

Thinking 只读取面向用户的安全标题和摘要；当前 Runtime 未提供这些字段时只显示状态，不展示原始推理。工具以紧凑动作行出现，当前项展开、完成项折叠，详情按“输入参数 → 输出结果”纵向排列；投影层同时隐藏敏感字段和绝对路径。
