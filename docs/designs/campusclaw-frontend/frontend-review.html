评审方式

本页沿用 Runtime HTTP 评审面的卡片结构和稳定评审键。每个界面状态使用固定 screenKey，依次评审作用、用户动作、系统约束和视觉材料；精确设计理由与源码证据仍以 Markdown 为准。

  2. 本 HTML：主要人类评审界面。

  4. low-fidelity.html：低保真布局源；PNG 为评审快照。
首次进入 / 选择 Agent 首次进入 firstUse 已实现 · 过渡 adapter

作用

让用户先选择一个受管 Agent，再进入真实任务会话；创建 Runtime Session、认证和默认模型初始化均在后台完成。

主要评审点

  • 是否以 Agent 能力而不是协议配置开始。
  • 首次进入是否需要单独高保真稿。
  • Agent 卡片的名称、描述和权限提示是否足够。
常规对话 常规对话 idleConversation 已实现 · 过渡 adapter

作用

围绕 Agent、Chat、消息、附件和工具活动完成日常任务。协议身份、ETag、原始 SSE 和凭据不进入产品主流程。

主要评审点

  • 近黑主动作是否符合 CampusClaw 品牌预期。
  • 工具 started/completed/result 是否应合并为一张活动卡。
  • 模型和深度思考是否保留在会话顶栏。
执行中控制 执行中 runningConversation 已实现 · HTTP 1.38.0

作用

让用户看懂 Agent 正在做什么，并通过“调整方向”“加入队列”“停止”控制唯一 active execution。

主要评审点

  • 当前跟进方式是否在发送前足够清楚，且无需两个常驻胶囊。
  • 绿色运行点与完成 check 的区分是否清晰。
  • 停止是否保持小型轮廓按钮，避免与主动作竞争。

本轮确认项

1. 是否确认三状态信息架构？

firstUse、idleConversation、runningConversation 作为首版稳定评审和测试边界。

2. 是否确认 Codex-inspired 视觉方向？

黑白中性层级、近黑主动作、少量绿色状态、蓝色仅用于焦点/链接；保留 CampusClaw 自有品牌。

3. 已确认：跟进交互与 Codex desktop 一致

desktop 默认“调整方向”，设置可切换“加入队列”；Cmd/Ctrl+Shift+Enter 对单条消息临时反转。“调整方向”不会硬中断当前模型或工具。
