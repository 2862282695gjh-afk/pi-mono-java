主 Agent 并发限流器结构

补「跨 Agent 全局并发上限」—— Agent.startExecution 边界 / 拒绝快、不阻塞

现状:executionLock 只保证单个 Agent 内部一次一个 run;虚拟线程无界;全仓无任何跨 Agent的并发上限。K 个主 agent 并发会同时打爆 LLM provider。本设计在 Agent.startExecution 边界加一个共享的 MainConcurrencyLimiter,策略是快速拒绝(沿用 executionLock 现有抛错风格),绝不阻塞 acquire。

两个维度别混:
  • executionLock = per-Agent(同一个 Agent 别并发跑两个 run)。原有的,不动。
  • MainConcurrencyLimiter = 全局(整个 JVM 同时有多少个主 loop 在跑)。新增的,共享一把 Semaphore。
检查顺序:先 executionLock(自己别重入),再 limiter.tryAcquire(全局别超)。

关键:拒绝而非阻塞。tryAcquire() 立即返回 false → 立刻 failedFuture,绝不 permits.acquire() 死等。原因:主 agent run 又长又可能持有资源,阻塞会让外部请求(HTTP/WS)挂着堆积,且和子 agent 的 SpawnGovernor 叠加时极易 hold-and-wait 死锁。拒绝是可恢复的(客户端/模型读到错误能重试),阻塞/死锁不可恢复。

策略因层而异:
  • MainConcurrencyLimiter(本图主角) + SpawnGovernor → 拒绝(非阻塞,沿用 executionLock 风格)。
  • LLM Provider 限流 → 重试/退避(同一调用可重试,配合已有 maxRetryDelayMs,可等)。
只有 provider 那层适合「等」;主并发和 spawn 那两层一律快速拒绝。
