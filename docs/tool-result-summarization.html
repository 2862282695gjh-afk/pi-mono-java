总览 一句话定位

CampusClaw 中不存在独立的「工具结果总结器」——工具结果的总结是上下文压缩（Compaction）链路的一部分：当会话上下文逼近模型窗口（阈值触发）或已经溢出（错误触发）时， SessionCompactor 把历史消息（含全部工具结果）交给压缩模型生成结构化摘要。 工具结果在该链路中有三个关键待遇： ① 进入总结提示词前被截断到 2000 字符； ② 以 [Tool result] 段落参与结构化摘要提炼； ③ 被压缩掉的 Read 工具所读文件路径由 FileOperationTracker 追踪，以 <read-files> 附加到摘要，保证「读过什么」可追溯。 保留窗口（keepRecentTokens）内的工具结果则原样保留、不参与总结。

核心 工具结果如何被序列化与截断

压缩时，CompactionPromptBuilder.serializeConversation 把每条消息转成文本段落。 工具结果（ToolResultMessage）以 [Tool result]: 前缀出现， 内容超过 TOOL_RESULT_MAX_CHARS = 2000 字符时截断并追加计数提示； 工具调用本身则以 [Assistant tool calls]: name(key=json, ...) 形式完整保留参数（这是刻意设计—— 工具参数是"做过什么"的精确记录，压缩后仍需可追溯）。
modules/coding-agent-cli/.../session/compaction/CompactionPromptBuilder.java
serializeConversation 中的消息分派（节选）
private static void appendMessage(List<String> parts, Message message) {
    if (message instanceof UserMessage user) {
        appendIfPresent(parts, "[User]: ", contentText(user.content()));
    } else if (message instanceof AssistantMessage assistant) {
        appendAssistant(parts, assistant);   // thinking / 正文 / tool calls 三段
    } else if (message instanceof ToolResultMessage result) {
        appendIfPresent(parts, "[Tool result]: ", truncate(contentText(result.content())));
    }
}

private static final int TOOL_RESULT_MAX_CHARS = 2_000;

private static String truncate(String text) {
    if (text.length() <= TOOL_RESULT_MAX_CHARS) { return text; }
    int removed = text.length() - TOOL_RESULT_MAX_CHARS;
    return text.substring(0, TOOL_RESULT_MAX_CHARS)
            + "\n\n[... " + removed + " more characters truncated]";
}
工具调用参数（toolCall）走 json() 序列化且不截断——参数体积通常远小于结果，且是摘要中「关键操作」的锚点； 只有结果被截断。摘要提示词同时要求模型「Preserve exact file paths, function names, and error messages」， 即截断丢失的正文细节由模型在摘要中优先挽救路径、函数名与报错三类高价值信息。

提示词 四种总结提示词的分工

提示词常量触发形态要点
系统提示词SYSTEM_PROMPT所有摘要调用的 system「只输出结构化摘要，不继续对话」
全量摘要SUMMARY_PROMPT无既往摘要固定六节：Goal / Constraints / Progress(Done·In Progress·Blocked) / Key Decisions / Next Steps / Critical Context
增量更新UPDATE_PROMPT存在 <previous-summary>保留旧信息、推进 Done、更新 Next Steps；允许可控删减
轮次前缀TURN_PREFIX_PROMPT单轮过大被切分（split-turn）只总结轮次前缀（Original Request / Early Progress / Context for Suffix），后缀原样保留
拆分轮次（splitTurn）时走 compactSplitTurn：历史摘要与轮次前缀摘要分别生成后以 --- **Turn Context (split turn):** 拼接。两者 maxTokens 预算不同——历史摘要 0.8 × reserveTokens， 轮次前缀 0.5 × reserveTokens。

条件判定动作

Usage 优先策略：优先取同 provider、同 model 且晚于最新压缩边界的最后一条有效 Assistant Usage （totalTokens，否则四项相加）；无有效 Usage 才退化为对尾部消息逐条估算。

可追溯 被压缩工具结果的文件清单（read-files）

工具结果被截断甚至整段消失后，「模型之前读过哪些文件」仍需可追溯。 FileOperationTracker.filesRead 扫描历史中所有 AssistantMessage 的 ToolCall，过滤 name == "Read"，提取文件路径参数，与既有摘要中的 <read-files> 集合合并（跨次压缩累加，TreeSet 去重排序）， 最终由 CompactionMessageSupport.appendReadFiles 以 <read-files> 段落追加到摘要尾部。
.../session/compaction/FileOperationTracker.java（节选）
filesRead — 从 ToolCall 提取 Read 路径
for (Message message : messages) {
    if (message instanceof AssistantMessage assistant) {
        assistant.content().stream()
                .filter(ToolCall.class::isInstance)
                .map(ToolCall.class::cast)
                .filter(call -> "Read".equals(call.name()))
                .map(ToolCall::arguments)
                .map(FileOperationTracker::readPath)
                .filter(path -> path != null && !path.isBlank())
                .forEach(result::add);
    }
}
摘要消息的完整形态（下次压缩时被 previousSummary 识别并增量更新）： The conversation history before this point was compacted... <summary>…</summary> <read-files>…</read-files> ——包装协议由 CompactionMessageSupport 的常量统一定义。

边界 防护与失败语义

摘要调用本身有严格的产物校验（summaryResponse）： ABORTED → CancellationException（手动取消不产生摘要）、 ERROR → IllegalStateException、 摘要里出现 ToolCall → 拒绝（总结模型绝不允许反向调工具）、 空白文本 → 拒绝。瞬态失败由 CompactionRetryClassifier 过滤后指数退避重试； 所有失败路径最终以 session.compaction.failed 事件落地，不影响原上下文。
压缩与普通消息互斥：/compact 命令或自动压缩在运行态被拒（busy）；「读取历史 → 压缩 → 写终态」期间普通消息不得并发， 避免摘要覆盖新消息。多实例下超时进入持久化禁止态，不按时间自动放行。
