01 总览:两层事件模型

CampusClaw 的事件体系是一个分层 + 单一广播器的设计。底层是 LLM 原始流式 token 事件,高层是 agent 生命周期域事件。两者之间由 AgentLoop 做翻译,由 Agent.emit() 这一个方法做集中分发。

所有事件的唯一出口都是 Agent.emit():它先把事件副作用投影到 AgentState(事件溯源),再 fan-out 给所有注册的监听器(异常隔离)。

一句话理解:生产端只管"发生了一个事件",把它交给 emit();分发器负责"更新状态 + 通知所有订阅者";消费端只管"我订阅了,收到事件就转成我的输出格式"。三者通过 方法引用 this::emit 这一根线串起来。

EventStream:命令式 emit 桥接 Reactor

EventStream<T, R> 是整个流式体系的基石。它把"生产者调 push()"这种命令式风格,桥接成 Reactor 的 Flux<T>(事件流)+ Mono<R>(最终结果)。关键机制:

modules/ai/src/main/java/com/campusclaw/ai/stream/EventStream.java:54-89
EventStream — 构造 + push() 自动终结
public EventStream(Predicate<T> isComplete, Function<T, R> extractResult) {
    this.isComplete = isComplete;
    this.extractResult = extractResult;
    this.eventSink = Sinks.many().unicast().onBackpressureBuffer();  // 无界缓冲,订阅前的事件排队
    this.resultSink = Sinks.one();
}

public void push(T event) {
    synchronized (lock) {            // 多线程并发 push 安全
        if (done) return;
        if (isComplete.test(event)) {   // 终结谓词命中 → 自动完结
            done = true;
            resultSink.tryEmitValue(extractResult.apply(event));
        }
        eventSink.tryEmitNext(event).orThrow();  // 终结事件本身也会投递给订阅者
        if (done) eventSink.tryEmitComplete();
    }
}
设计亮点:终结逻辑用 isComplete 谓词 + extractResult 函数参数化——EventStream 本身不知道"什么算终结",由子类/调用方注入。AssistantMessageEventStream 注入的就是"DoneEvent 或 ErrorEvent 即终结"。

AssistantMessageEventStream:终结条件特化

modules/ai/src/main/java/com/campusclaw/ai/stream/AssistantMessageEventStream.java:34-51
AssistantMessageEventStream — 特化 EventStream
public AssistantMessageEventStream() {
    this.delegate = new EventStream<>(
        AssistantMessageEventStream::isTerminal,       // DoneEvent || ErrorEvent
        AssistantMessageEventStream::extractMessage);  // 从终结事件抽 AssistantMessage
}

private static AssistantMessage extractMessage(AssistantMessageEvent event) {
    return switch (event) {
        case DoneEvent e -> e.message();
        case ErrorEvent e -> e.error();
        default -> throw new IllegalStateException(...);
    };
}

04 核心分发器:Agent.emit()

整个事件体系最关键的方法。Agent 是一个 Spring @Service 门面,既是 agent 运行时的配置入口,也是唯一的广播器。

订阅:CopyOnWriteArrayList + 返回取消句柄

监听器存在 CopyOnWriteArrayList 里(遍历安全,适合读多写少)。subscribe() 返回一个 Runnable 作为取消订阅的句柄——典型的"用闭包持有引用、调用时移除"模式。

modules/agent-core/src/main/java/com/campusclaw/agent/Agent.java:72,212-216
Agent — 监听器容器 + subscribe
private final CopyOnWriteArrayList<AgentEventListener> listeners = new CopyOnWriteArrayList<>();

public Runnable subscribe(AgentEventListener listener) {
    Objects.requireNonNull(listener, "listener");
    listeners.add(listener);
    return () -> listeners.remove(listener);   // 取消订阅句柄
}

emit():状态投影 + 异常隔离 fan-out

这是事件流的唯一汇聚点。两步走:

  1. applyEventToState(event)——把事件副作用投影到 AgentState(流式标志、pending tool calls、消息列表)。这让 AgentState 成为事件的函数,本质是事件溯源。
  2. 遍历 listeners 逐个 onEvent——每个调用包在 try/catch 里。单个监听器抛异常只记 log.warn,不会拖垮整个 agent run。
modules/agent-core/src/main/java/com/campusclaw/agent/Agent.java:275-322
Agent.emit() — 核心分发器
private void emit(AgentEvent event) {
    applyEventToState(event);                  // ① 事件溯源:更新 AgentState
    for (var listener : listeners) {
        try {
            listener.onEvent(event);            // ② fan-out 给每个订阅者
        } catch (RuntimeException e) {
            // 监听器不应中断 agent 运行,只在日志里暴露 bug
            log.warn("agent event listener threw exception (event={})",
                     event.getClass().getSimpleName(), e);
        }
    }
}

private void applyEventToState(AgentEvent event) {
    switch (event) {
        case AgentStartEvent ignored -> { state.setStreaming(false); state.clearPendingToolCalls(); }
        case AgentEndEvent e -> { state.setStreaming(false); state.replaceMessages(e.messages()); }
        case MessageStartEvent e -> { /* AssistantMessage → setStreaming(true) */ }
        case MessageUpdateEvent e -> { state.setStreaming(true); state.setStreamMessage(e.message()); }
        case MessageEndEvent e -> { /* setStreaming(false) */ }
        case ToolExecutionStartEvent e -> state.addPendingToolCall(e.toolCallId());
        case ToolExecutionEndEvent e -> state.removePendingToolCall(e.toolCallId());
        default -> {}
    }
}
同步 fan-out 的隐含约束:监听器在 agent loop 所在的虚拟线程内联调用(非异步派发)。因此监听器必须非阻塞——一个慢监听器会直接拖慢整条事件流水线。各消费端(如 WebSocket handler)需要自己把事件异步推到网络层。

05 事件生产路径:AgentLoop

AgentLoop 是 agent 的核心编排器:流式拉取 LLM 响应 → 翻译成域事件 → 执行工具 → 决定是否继续下一回合。

回合循环:AgentStart → (Turn 循环) → AgentEnd

modules/agent-core/src/main/java/com/campusclaw/agent/loop/AgentLoop.java:89-138
runInternal — 主循环与事件发射点
private List<Message> runInternal(...) {
    AgentEventListener eventListener = listener != null ? listener : event -> {};
    eventListener.onEvent(new AgentStartEvent());
    try {
        while (!signal.isCancelled()) {
            eventListener.onEvent(new TurnStartEvent());
            AssistantMessage assistantMessage = invokeModelTraced(...);
            eventListener.onEvent(new MessageEndEvent(assistantMessage));
            if (stopReason == ERROR || ABORTED) {
                eventListener.onEvent(new TurnEndEvent(...));
                break;
            }
            var toolCalls = extractToolCalls(assistantMessage);
            if (!toolCalls.isEmpty()) {
                runToolPhaseTraced(...);   // 内部发 ToolExecution* + TurnEnd
                continue;
            }
            eventListener.onEvent(new TurnEndEvent(assistantMessage, List.of()));
            if (followUpMessages.isEmpty()) break;
        }
        return context.messages();
    } finally {
        eventListener.onEvent(new AgentEndEvent(context.messages()));   // finally 保证一定发
    }
}

低→高层翻译:consumeStream()

这是两层事件模型连接的地方。AgentLoop 迭代 AssistantMessageEventStream 的 Flux,把每个低层事件翻译成高层 MessageStartEvent / MessageUpdateEvent。

modules/agent-core/src/main/java/com/campusclaw/agent/loop/AgentLoop.java:255-277
consumeStream — 低层流事件 → 高层域事件
private StreamConsumeResult consumeStream(AssistantMessageEventStream stream, ...) {
    AssistantMessage assistantMessage = null;
    var assistantStarted = false;
    // takeUntilOther(cancelSink):取消信号一到达就停止迭代
    for (var event : stream.asFlux().takeUntilOther(cancelSink.asMono()).toIterable()) {
        if (signal.isCancelled()) break;
        var currentMessage = extractAssistantMessage(event);
        if (!assistantStarted) {
            listener.onEvent(new MessageStartEvent(currentMessage));  // 首事件 → Start
            assistantStarted = true;
        }
        if (!(event instanceof AssistantMessageEvent.StartEvent)) {
            listener.onEvent(new MessageUpdateEvent(currentMessage, event)); // 其余 → Update(带原始事件)
        }
        assistantMessage = currentMessage;
    }
    return new StreamConsumeResult(assistantMessage, assistantStarted);
}
为什么 Update 事件带原始 event?MessageUpdateEvent(message, event) 第二个参数就是原始的 AssistantMessageEvent。消费端(如 TUI)可以据此区分"这是文本增量"还是"工具调用增量"并分别渲染,而不用自己重新解析。

取消与中止

CancellationToken 通过 signal.onCancel(() -> cancelSink.tryEmitEmpty()) 接入 Reactor。取消时 takeUntilOther(cancelSink) 打断 Flux 迭代,synthesizeAbortedMessage() 合成一个 StopReason.ABORTED 的消息让外层循环干净退出(避免 result().block() 在已拆除的流上挂死)。

工具执行阶段的事件由 ToolExecutionPipeline 在执行工具时产生。ToolExecutionUpdateEvent 来自工具自身的 partialResult 回调(如 bash 工具边跑边输出)。

modules/agent-core/src/main/java/com/campusclaw/agent/tool/ToolExecutionPipeline.java:100-118
invokeTool — partialResult 回调触发 Update 事件
private Outcome invokeTool(AgentTool tool, ToolCall toolCall, ...) {
    try {
        validateArguments(tool, validatedArgs);
        var result = normalizeResult(tool.execute(
            toolCall.id(), validatedArgs, signal,
            partialResult -> eventListener.onEvent(new ToolExecutionUpdateEvent(
                toolCall.id(), toolCall.name(), validatedArgs, partialResult))));
        return new Outcome(result, false);
    } catch (Exception e) {
        return new Outcome(errorResult(messageForException(e)), true);
    }
}

08 关键设计特性

设计决策一览
① 单一广播器 + 异常隔离 所有事件汇入 Agent.emit(),fan-out 时每个监听器 try/catch 包裹——坏监听器不污染 agent run
② 事件溯源式状态 applyEventToState 让 AgentState = 事件的函数,状态完全由事件驱动,可重放推导
③ 分层解耦:生产/分发/消费 AgentLoop(生产) ↔ Agent.emit(分发) ↔ 各 Mode(消费),三者靠 AgentEventListener 接口 + this::emit 桥接,可独立单测
④ 嵌套 payload 保真 高层 MessageUpdateEvent 携带原始 AssistantMessageEvent,生命周期信号与细粒度增量兼得
⑤ Reactor 桥接 + 虚拟线程 EventStream 用 Sinks 把命令式 push 桥接成 Flux;AgentLoop 在虚拟线程跑,CancellationToken 经 cancelSink 接入 Reactor 取消
⑥ 同步 fan-out 约束(需注意) 监听器内联调用,必须非阻塞;慢监听器会拖慢流水线,网络/IO 须消费端自行异步化
